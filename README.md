**K 執行中樞｜通用工作台**

K 是供個人使用的 AI 工作台。你在同一個介面交代工作、查看結果、處理核准與停止工作；背後由 Codex、Claude Code 或 Antigravity 三個原生核心執行，沿用各自的官方訂閱與權限，不另改走 API 計費。用途是一般文件、資料與程式工作，不接入病歷或 CaseAgent 正式流程。

### 個人模型分工

一般工人優先 Gemini 3.8 Flash；文章、審美、Google 商家相關工作也以 Gemini 為主，文章最後常請 Opus 5.5 提供第二意見，而非由它說了算。Opus 5.5 是平常討論方向的大腦；**GPT-6.1 Sol 是取代 Astra 的日常技術主腦（小 Astra）**，負責理解需求、規劃、架構、後端判斷、除錯、派工、測試與驗收，不只是監工。Astra 只有本人明確選用且實際可用時才使用；Luna 除本人明確指定外，只在小任務特別要求嚴格遵守規則時使用。

這樣分工依據本人的使用經驗：Sol 後端較強、額度消耗少，適合作為 Opus 與 Flash 之間的技術中間層，分攤工作與用量，不取代 Opus 的通才角色；不是官方能力排名或額度保證，也不為平均額度硬派工。

大量寫碼重視快速產出，優先交給 Flash，不預設交給較慢的 GPT／Luna。GPT 留給技術判斷、檢查與必要補修；等待工人時用既有完成通知或等待工具，不反覆查進度消耗主代理額度。本人明確指定其他模型時仍照指定。

程式通常由 Flash 快速實作與修正，Sol 按批次或完成結果檢查，不一直查進度。只要仍有進展，可以讓 Flash 多修幾次，不訂固定失敗次數；確實卡住、反覆同錯或越改越糟，才由 Sol 親自改，再不成才交 Opus。接手前先查清楚已完成什麼，不重做整份工作。目前可在 Opus 討論後交接到 Sol 主聊天室，由 Sol 派 Flash；**Opus 派 Sol 子代理、Sol 再派 Flash 的自動串接尚未提供**。這次只更新 AI 指引，不新增分層派工，生效狀態見[Sol 技術主腦紀錄](docs/sol-technical-lead-20261004.md)。

Opus 5.5 也負責檢查 GPT 程式碼是否過度工程化；**Sol 寫碼後必須交真正的 Opus 5.5 審核**，未審就保留待審狀態，不用自查或其他模型冒充，也不另做提醒或確認流程。這些是交給 AI 的分工指引，不是新增自動審查系統或強制切換模型；已有手動指定仍優先。Gemini 做完後由你在另一個 GPT／Claude 聊天室複查，不需要反向派工。指引接入與正式生效狀態見[模型分工紀錄](docs/model-role-guidance-20261003.md)。

Gemini 需要另外安裝 Antigravity CLI（agy），首次開啟需完成官方初始化，再由本人在官方程式開啟的外部瀏覽器登入；Chrome 為預設瀏覽器時會開 Chrome。在 K 的「設定 → 帳號連線」按「新增 Gemini 帳號」，由本人完成官方登入；若要求手機／QR 驗證，請一併完成。關閉官方 Antigravity／agy 視窗後，回 K 按「登入完成，保存帳號」。設定會列出保存的帳號，側欄與額度視窗顯示官方 5 小時／每週剩餘額度。K 不讀取 Chrome 登入資料或接收 Google 授權碼。Gemini 的「工作區編輯」只允許工作區寫檔，命令與額外寫入直接拒絕；若要授予完整能力，需明確選用「完整存取權」。Gemini 3.8／3.7／3.6 Flash 與 3.1 Pro 支援圖片、原始 PDF（含掃描頁）、WAV／MP3／M4A 音訊及 MP4 影片；Flash 工人也可依授權讀取工作區內的原檔。K 不另設附件份數、單檔大小、擷取文字量或 PDF 頁數上限；實際處理仍依目前原生核心、模型與電腦可用資源，不保證任意大的檔案都能處理。預覽可節錄顯示，附件原檔與下載保留完整內容。GPT／Claude 可在待送訊息按「立即送入」補充附件；Gemini 執行中仍使用待送佇列。聊天只顯示使用者文字與附件卡片，不展開內部附件提示。較大檔案可交代 AI 依工作區路徑讀取，仍受原生限制，長影片尚未驗證。未知的新型號不冒稱已驗證，GPT／Claude 的影音附件未因此開放。本批驗收與各台部署狀態見[多模態與工具紀錄](docs/gemini-capabilities-20261004.md)。Gemini 主代理與 Flash 工人已完成原生搜尋、讀公開網頁，以及 K Chrome 開頁、點擊、截圖實測；原生讀網址可能回快取，最新或動態內容改用 Chrome。唯讀模式不提供互動瀏覽器，登入／驗證仍由本人操作；本批已套用南區並推上 GitHub，東區尚未更新，詳見[網頁與瀏覽器紀錄](docs/gemini-web-browser-20261004.md)；Gemini 主代理不派 GPT／Claude，成果由你另開聊天室複查。開發完成不等於兩台電腦都已更新，最新驗證及部署界線見[南區部署紀錄](docs/flash-deploy-claude-review-20261003.md)。

### Google 商家營運工具

在南區 K 選用 AdsControl 或上一層營運工作區，AI 現在能直接查詢商家帳號、據點、評論及既有貼文，不必開網頁逐一找。Gemini 主聊天室與 Flash 工人已實際驗證；GPT／Claude 也已接線，但尚未各自完成真模型查詢驗收。商家授權與 Gemini Pro 模型帳號分開，不會因切換工人帳號改用另一間商家。

這批只有查詢，**不含發文、回評、影片上傳或改廣告**，也不是所有 Google 服務都已接通。接線只在這台完成，東區不會從 Git 取得南區的登入資料；詳見[接入與部署紀錄](docs/google-ops-connect-20261004.md)。

## 怎麼啟動、更新與退版

### 啟動

使用既有桌面捷徑開啟 K；或在 K 安裝資料夾執行 `Start-K-Desktop.ps1`。第一次在新電腦使用，需要本人登入官方訂閱並選擇本機工作資料夾，不搬另一台的登入資料。可直接在「設定 → 帳號連線」登入 GPT／Codex、Claude，或開啟 Gemini 官方登入，不必先新增對話；新對話也保留同一組登入入口。

### 安裝與更新

**以已驗收的 Git 版本更新，不直接追最新開發分支。** 每批完成測試、主代理與 Opus 5.5 複查並處理問題後，才部署、正式讀回及推上 GitHub。AI 會從[工程索引](docs/development-log.md)確認固定程式版本；東區等下次到當地，更新到同一個已驗收版本，不搬南區的帳號或對話。

首次安裝用 `Setup-K.ps1 -Ref '<已驗收版本>'`，並指定本機官方核心路徑；既有安裝取得 Git 來源後，再用 `Update-K.ps1 -Ref '<已驗收版本>'`。取得 Git 來源不等於更新正式 K，執行更新器才替換實際程式。更新前先在 K 選「離開並停止 K」，不要只關閉視窗。更新先準備、建置與測試新版，成功後才替換，不強制停止工作，並保留上一版可退回。

三家原生核心另外在「設定」按 **更新 Claude Code／更新 Codex／更新 Antigravity**；平常不自動查新版或更新。按下後才查詢，有新版才下載，完成工作並「離開並停止 K」、重開後生效。這不是更新 K 本身；舊核心保留、不動登入。此入口已套用南區並推上 GitHub，東區仍待下次更新；詳見[手動核心更新](docs/git-install-update.md#三家原生核心的手動更新)。

### 退回上一版程式

同樣先「離開並停止 K」，再執行 `Update-K.ps1 -Rollback`，完成後重新啟動。

**程式退版只退程式與啟動器，不把對話還原到以前的狀態。**

詳細步驟與所需環境見 [Git 安裝、更新與退版指南](docs/git-install-update.md)；需要協助時，可請 AI 依這份指南處理。

## 已知限制與使用決定

### 帳號

K 可以同時連接 GPT、Claude、Gemini 三家訂閱。GPT／Claude 目前仍各用一個登入；Gemini 可直接新增帳號，登入後保存於這台電腦，並逐帳號顯示登入與額度。**四個真實帳號已保存，免重新登入切換、官方額度與 K 帳號畫面均已實測**，南區 K 已回原帳號並重開。真實額度不足後的工人接手尚未完成驗收，目前進度見[新增帳號與實測紀錄](docs/gemini-login-flow-20261003.md)。

尚未加入帳號時，Gemini 照常沿用目前 Antigravity 登入。加入後逐個帳號使用，共用專案設定，不合併額度，也不讓不同帳號同時工作；官方程式必須關閉才能由 K 協調。工人額度用完後，要先確認停止，再由主代理檢查成果，以新工人接續剩餘工作，不重播整份任務。真實帳號操作須本人登入；同帳號同時啟動曾誤判成正在切換帳號，本批已修正前置檢查；沒有自動重送，詳見[修正與驗收](docs/worker-count-20261004.md)。

Gemini 保存帳號可依序切換；同一帳號支援多個工人並行，不同帳號並行不列入目前開發目標，也不採第三方 OAuth 外掛。使用偏好是持續使用一個帳號，官方確認 5 小時或每週額度耗盡，才按保存順序換下一個可用帳號接後續工作；5 小時用完不必等週額度耗盡或該時段恢復。不平均分散、不每次派工輪換，也不因前一帳號重置就切回。本人明確選用帳號仍優先。這是用量管理，不保證降低官方帳號風險；指引、程式及生效界線見 [帳號使用指引](docs/gemini-account-policy-20261004.md)。額度查詢逾時不等於登出；既有修正與實測範圍見 [子代理與帳號修正](docs/worker-count-20261004.md)。

官方額度查詢偶爾無法確認時，畫面會保留並標示上次資料，可按「刷新目前帳號額度」重新確認，不代表一定要重新登入。

新增帳號前，請先等 Gemini 工作停止並關閉官方 Antigravity／agy。已有原帳號時，「取消新增」會回原帳號；原本未登入時，取消只取消加入 K，不會替你登出剛完成的官方登入。第一次加入帳號後，舊的未綁定帳號 Gemini 對話需開新對話交接；不搬原生歷史，也不動 Chrome 的 Google 登入。

### 目前不提供

以下是**尚未設計的功能，不是功能做壞**；有實際需要時再個別設計，不先列為必做項目：

- **歷史回溯**：把對話退回先前某一步。查看舊訊息或接續舊對話不等於回溯。
- **檔案還原**：把工作檔案恢復成先前版本。
- **即時語音對話**：與 AI 連續語音交談；目前只有聽寫成文字。

### 封存與資料

**封存＝放棄。** 不要把封存當成備份；K 不提供封存對話的資料備份或還原服務。程式的可退版版本也不是對話備份，需要的內容請在封存前另行保存。

### 語音與新電腦

- 東區 Windows 10 使用 `Setup-K.ps1 -Ref '<已驗收版本>' -DictationProvider windows` 設定 Windows 內建繁體中文（臺灣）辨識，不需 Python、Whisper 或 NVIDIA。安裝與驗證狀態見 [東區紀錄](docs/dongqu-install-20261002.md)。
- 現行本機 Whisper 需要 **NVIDIA 顯卡**、相容的 CUDA 環境、Python 與模型檔，不是可直接搬到任意電腦使用的套件。
- 聽寫來源由各台電腦獨立選擇，存在本機設定；未設定時預設 Whisper，更新會保留既有設定，南區不會因取得程式更新而自動切換。
- 沒有準備語音環境，仍可使用文字聊天室。Git 版本不包含語音模型或本機登入資料。
- 東區那台的 Windows 10 安裝、本人登入、Chrome 助手、真麥克風與剪貼簿操作仍需在當地驗收；本機測試通過不等於已驗證另一台電腦。
