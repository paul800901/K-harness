# 多模型討論規則

2026-10-21 自 `AGENTS.md` 第九節原文移出（原文未改寫），因 agy 單一規則檔上限 24,000 bytes，超過會被截斷。這些仍是現行有效規則；修改討論功能、擔任討論主持或參與者前先讀本檔。`AGENTS.md` 保留摘要與指向本檔的連結。

- 多模型討論（平行比較、交叉審查、多人討論）：輸入框上方的討論設定只是設定，送出照常交給聊天室主模型；K 把設定像技能一樣附在本人訊息後（畫面只顯示本人原文）。本人要求開始時，主模型寫出討論任務書（目的、要做的事、它讀到的檔案與網頁原文、範圍、未知）並加開始標記，K 在該回合結束後直接開始討論；只看附了設定的那一輪，不從歷史或重啟後復活。參與者以任務書為主要材料，不自行翻找整個工作區。最後整理列出各家想法、共識與分歧，主模型不當裁判；本人要統整時再請主模型做。每場討論開始後消耗該次模式設定，結束後下一輪預設一般對話；本人重新選模式才再次討論。尚未發起時可繼續規劃，參與者選擇、進行中插話與歷史紀錄保留。
- 討論參與者可廣泛唯讀整台電腦的相關資料，含工作區外絕對路徑，不設憑證名稱排除清單或讀檔申請；不得寫入、執行改變狀態的操作或派工。Claude 僅五項讀取／搜尋工具；Gemini 保留原生寫入、命令與 MCP deny；Codex 使用 read-only＋never，Windows readiness 非 ready 不開。設定與模擬測試不能代替真實原生權限驗證。
- 主持由現有聊天室主代理的同一 native session 擔任，沿既有送訊息與工人通知排程，不另開主持 session。主持內部回合以持久識別碼從聊天投影隱藏，安排存入 decisions；討論停止只中止所屬主持回合與參與者，不關主 session，不停止一般工人。離線或送出不明不得重送。一般子代理的權限、排程與顯示不變。
- 討論原文保留，聊天室呈現一張入口卡與 AI 整理；右側圓桌按席位與批次閱讀，舊紀錄只在顯示時推估。停止／插話綁 threadId＋runId，過期操作拒絕。
- 討論用 API 連線：用於平行比較、交叉審查與多人討論；2026-10-23 起也可作唯讀諮詢子代理（見 `docs/api-consult-worker-20261023.md`），仍不進主模型。API 參與者依上述廣泛唯讀規則取得原始資料（本人已接受材料外送，不反覆確認），僅提供列檔、搜尋與讀檔，保留路徑、連結、一般檔案與讀取前大小檢查。API Key 由本人在設定頁填入以 K 命名的 Windows 憑證，不讀用舊 Key。查證優先用原生搜尋；API 端用官方匿名免費的 Exa，不裝本機搜尋服務，也不靜默改成付費。
