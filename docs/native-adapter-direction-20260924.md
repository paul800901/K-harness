# K 原生接入方向

使用者於 2026-09-24 確認：**K 共用介面，各供應商走自己的原生接法；沒有等價能力就明確標示，不硬湊。**

K 管呈現與必要協調，供應商原生核心管執行、歷史、壓縮與權限。不得引入另一套歷史權威、憑空估計上下文、以提示詞冒充原生審查/回溯，也不改用 API 計費來補訂閱能力。

## 優先順序與驗收
1. 通知：錯誤/警告、模型改派、Windows 沙箱就緒。確認全域警告不被 thread filter 丟棄，不錯放其他對話事件；不自動重送。
2. 呈現：原生公開摘要放入摺疊過程、唯讀檔案差異、上下文用量。未知維持未知，不把訂閱額度、累計 token 當上下文占用率。
3. 操作：工作區 @ 檔案搜尋、明確啟動原生審查。不自動提交草稿；沒有等價功能明示不可用。
4. 另行設計：歷史回溯不等於檔案還原；即時語音先確認訂閱、費用和隱私，不自動開啟。
