# 成果不再自動打開右側面板（2026-10-26）

## 起因

本人在 CaseAgent 聊天室看到右側「成果」欄自動打開，問是否只要有成果就一定跳出。實查 `frontend/main.jsx` 當時的行為（電腦版）：

- 對話中出現沒見過的成果檔，就打開面板並切到「成果」分頁，即使本人先前手動關掉。
- 第一次點進某聊天室時，有成果檔或瀏覽器分頁就打開。
- 「已關閉」只記在記憶體，K 重開後又會自動打開。
- 手機版本來就不自動打開。

本人原話要點：成果欄實際使用次數是零、習慣上不會往那邊看；不要完全移除（哪天需要備份或看檔案時還能看），但不要自動打開。真的需要成果會直接問該聊天室的 AI，所以也不要加提示。

## 差異

- `frontend/main.jsx`：成果檔不再讓面板自動打開或切換分頁。電腦版只有兩種情況會開：本人按右上角面板按鈕，或第一次看到開著 K 瀏覽器分頁的聊天室（瀏覽器協作照舊）。之後維持本人在該聊天室最後的選擇。移除「已見過的成果檔」記錄與相關判斷；手機版行為不變。
- `test/completion-attention-ui-probe.mjs`：在既有「沒有強制打開面板」檢查前送入新成果檔，確認面板仍保持關閉。

## 驗證

- 新檢查先在舊程式上跑：失敗（`no forced panel, even for new results`），證明能抓到舊行為；新程式通過。
- `npm test` 1952/1952。
- `npm run build:ui` 後 `npm run test:ui` 50/51：`voice-room-switch` 在 0.5 秒時因 remote 連接埠未就緒失敗，單獨重跑通過（與既往紀錄同類的連續執行搶埠，與本次修改無關）。

## 複查

主代理即 Opus 5.5（`claude-opus-5-5`），自行撰寫並複查：改動以刪除為主，桌面首次進房只依瀏覽器分頁決定、之後沿用本人選擇；手機分支邏輯與舊版等價（`previous?.open === true` → `previous === true`）；chooseInspector 只記開關。改動小、未另派 Sol 抓錯或 Fable 第二審。
