# 移除 150% 介面縮放（2026-10-14）

## 決定

[介面實測整修](ui-probes-20261014.md)發現 900×700 視窗加 150% 縮放時版面擠壓（頂部折行，排隊編輯的送出鈕被推出畫面、聊天內容只剩約 76 像素）。本人先決定暫不修，接著指示：「那這樣介面縮放150%就直接拿掉吧」；此前說明日常最多用 125%，150% 是當初的特殊需求。

## 修改

- `frontend/appearance.mjs`：介面縮放選項改為 90／100／110／125%。之前存過 150% 的設定，讀取時沿既有「取最接近選項」規則自動變為 125%，不另寫轉換程式。
- `test/appearance.test.mjs`：驗證已存的 150% 讀成 125%。
- 介面實測：10 個實測的 900×700／150% 情境改為 900×700／125%（目前最大縮放）；`menu-viewport` 的 900×600 情境由 150% 改 125%。`queue-edit`、`process-details` 刪除 150% 情境，連同只為它存在的「已知退化」清單、`KNOWN REGRESSION` 回報與執行器的彙整一併移除，不留無用程式。
- 介面縮放選單直接由選項清單產生，不需改其他元件。

## 驗證

- 完整測試 1649／1649；46 個介面實測全數通過（`npm run test:ui`）。與[討論 API HTTP 400](discussion-api-400-20261014.md) 的修正同批。
