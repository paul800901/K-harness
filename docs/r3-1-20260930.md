## 變更與根因

### 1. 模型選單使用官方目錄

- 移除 unified-controller 與前端的 GPT 白名單。保留原生 hidden 過濾，依 provider 分組，不再把舊 Sol 從官方清單額外隱藏。
- Claude Code **2.1.280 實際 initialize 有 models**。以正式 K 專用官方執行檔／設定目錄唯讀初始化，未送 user 訊息；再以候選 `createClaudeController.models()` 實際讀回 4 個去重後項目，`threadId=null`、`busy=false`，查詢程序已關閉。
- 查得 Opus、Fable、Sonnet、Haiku；這只是當時目錄，不是 K 新增的固定名單。移動別名使用官方 `resolvedModel` 保存，已具體版本的 value 保留（含 `[1m]`）；`--model` 跟對話保存值走。模型切換與再次開啟也保存該值，不自動改用其他模型。
- 推理選項使用 `supportedEffortLevels`；只有未提供 models 欄位的舊 initialize 保留原單一 Opus 相容路徑，舊推理清單收成一個常數。原生明確空目錄不補假模型。
- 官方 Fable 說明含 **Requires usage credits**，前端現在顯示選中模型的官方 description，不只顯示名字。不自動選用它，也沒測付費回合。Claude 訂閱檢查、Codex `account/read=chatgpt` 與不得 fallback API 的規則不變。
- 目錄可讀不代表每個新模型已跑過真正工作；本批沒有新 AI 模型回合，避免消耗 Opus／GPT 執行額度。

### 2. 移除工人測試器

- `coding.mjs` 只保留 `replace_code`，修改前備份、精確前文、大小／路徑界線保留；刪除 `run_tests`、`runFixedTests`、`testRunner` 參數及 coding 的 `testFiles`／`timeoutMs`。
- 同步 worker、dispatcher、isolated-desktop 與 MCP schema／說明；MCP 版本 0.2.0 → **0.3.0**。測試由父代理自己跑，沒有改成另一種工人 shell。
- 舊 job 照讀，不遷移、不重送；舊含測試權限的紀錄與新請求視為不同 request。既有 `recovery.mjs` 本來只處理 editFiles，不需額外改動。
- 刪除失效的 `test/coding-sandbox-runner.test.mjs`。候選及 D 驗證副本兩份均用 Windows 資源回收筒 API 處理；收尾讀回回收筒的 DeletedFrom 為這兩個確切 test 目錄。原始碼另保留 Git 歷史。未清理其他檔案。

### 3. 連線中可取消

- 根因不是 AI 工作忙：新房間尚未進 rooms，stop 找不到；兩家 controller 又在 opening 時拒絕 stop。
- conversation-controller 在 open 一開始保存可取消的 handle；前端新對話設定先關閉，顯示「正在載入對話…／取消連線」，取消不被原全域 action disabled 擋住。
- AbortSignal 連到 Claude preflight、stream initialize、Codex catalog／app-server 初始化；只結束本次新開的 host，不停止其他房間。不重送任何訊息。
- Claude 初始化失敗先等待其真子程序退出才拋錯；晚到的 host 會關閉，不採用、不變 ready。Codex 已中止 host 不再轉送晚到事件。取消後可再開。
- `abortable.mjs` 僅負責初始化等待的取消，不是重試／fallback。已中止的 promise 仍接收 rejection，避免晚到失敗成為 unhandled rejection。

### 4. 正常退出失敗後的最後出口

- `KTrayLauncher.cs` 保留原正常關閉流程。拒絕、逾時或無法確認後才顯示工作單指定的 Yes/No 對話框；**預設 No**。
- 選 Yes 才對啟動器持有的 supervisor PID 執行 `taskkill /PID /T /F`；不依程序名稱／連接埠找目標，不自動強制結束。確認及結果寫 launcher.log。
- 關閉後仍沿用既有 uncertain／interrupted 與不重送機制：重開查原工作、既有成果與歷史；不能把遭中斷工作當完成。不是新增復原或自動續跑系統。
- 已用 `local-launcher\Build-K-Launcher.ps1` 重建候選 exe：`C:\Users\Paulus\.codex\worktrees\r2-simplification\K-harness\local-launcher\dist\K桌面啟動器.exe`。SHA-256：`9DDA897D52C476C6D260D3BE5A8E4160E7DA6D0AD6F8250C30D99FAAEE3193DC`。dist 依原規則不入 Git，日後也可從標記重建；沒有替換正式系統匣 exe。
- 假 supervisor 的實際 Windows 對話框：先按 Enter，預設 No 得 `stop=False alive=True`；第二次選 Yes 得 `stop=True exited=True`，supervisor PID 7140 與其子程序 PID 37000 都已退出。正式 K 沒有被停止。

### 5. 共用原子寫入及小修

- 新 `atomic-write.mjs`：同目錄獨立暫存檔 → write／fsync／close → rename。完全沿用 R2 的 EPERM／EACCES／EBUSY 有限重試：最多 20 次等待、排定等待合計 775 ms；只重試同一份已完整寫出的 rename，不重做工作。其他錯誤及用盡仍拋出，失敗暫存檔保留，原檔不被部分覆寫。
- 六處改用：main-sessions、input-queue、ui-message-timing、Claude saveRecord、Luna persist、projects。既有序列化佇列與 R1/R2 相容檔名不變。
- luna-gateway／mcp／worker 非 Error 拋值保留 `String(error?.message ?? error)`；Electron 子程序環境多排除 NODE_OPTIONS，其他 OS／工具變數不變。
- Luna close 不再對已結束的**歷史**工作逐筆 thread/read／cancel。本輪測試抓到「本 host 已完成的 turn 仍有背景終端」不能一起跳過，因此只記錄本 host 建立的 thread 集合，這些仍收尾背景終端；未結束工作仍照舊 cancel。清理失敗仍報錯，不能假稱全關。
