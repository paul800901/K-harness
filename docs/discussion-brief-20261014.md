# 多模型討論：主理人任務書與確認後送出（2026-10-14）

## 起因

一場交叉審查（請各模型評論 Gemini 對官網首頁的意見）先因 HTTP 400 失敗，重跑後雖成功，但各模型花大量力氣自行翻找工作區、比對網站版本，最後只得到一長串查證與分歧。本人指出：「網頁本體不是讓他們自己去查」；參與者需要的只是 Gemini 的意見與網頁本身。原本的流程是本人直接輸入需求，K 把原文加上整個工作區（約 3 萬個檔案）的讀取權交給參與者，並要求 API 參與者「自主列檔、搜尋、不能只信主持人的摘要」，參與者只好自己找材料。

本人提議：三種模式（平行比較、交叉審查、多人討論）都由該聊天室的主模型擔任 AI 主理人，先把需求整理成適合討論的格式再送出，而不是由本人直接填寫。

## 本人決定

1. 主理人整理好任務書後，**先給本人確認再送出**。
2. 最後的「討論整理」**維持現狀**：列出各模型的想法、共識與分歧，主理人不當裁判；本人需要統整時，直接在聊天室請主理人做（討論結束後主理人本就看得到完整紀錄）。

## 修改

- `src/discussion-controller.mjs`：原「背景摘要」一步改為「討論任務書」。主理人（聊天室主模型）依模式寫出目的、本次要做的事、材料、範圍（以任務書為主、需要核對時可讀哪些具體檔案或網址、哪些不必查）與未知事項。材料的規則：被審查內容與附件 K 會另行原文附給參與者，任務書只指出看哪一段、重點是什麼，不整段複製（避免輸入倍增）；網頁可由主理人用讀網頁工具取回原文；**主理人讀不到本機檔案**（討論模式的原生工作階段自 10-08 起就不開本機讀寫工具），檔案內容只能來自對話與附件，沒讀到的列入未知，不得憑記憶補寫。平行比較仍不得放入原模型的候選答案、結論或立場。任務書以「討論任務書」顯示在聊天室後進入新狀態「等待你確認任務書」；**確認前不開啟、不詢問任何參與者**。取消沿用既有停止；等待中補充訊息會被擋下並提示。K 在等待確認時重啟，讀回為「已停止，沒有送給任何參與者」，不自動續跑。
- 參與者收到的材料欄位由 `background` 改為 `brief`，提示「主理人任務書是本次的主要材料與範圍；需要核對時才讀其中指定或相關的原文，不必另外翻找整個工作區」。
- `src/discussion-api.mjs`：API 參與者的系統指示由「自主列檔、搜尋、不能只信主持人的摘要」改為「以主理人任務書的材料為主；需要核對才讀指定或相關的具體檔案／網頁，不要列出或搜尋整個工作區；任務書是整理，不是事實保證」。
- `src/conversation-controller.mjs`、`src/desktop-server.mjs`、`src/remote-access.mjs`：新增 `/api/discussion/confirm`（手機遠端亦可確認）。
- `frontend/discussion-controls.jsx`、`frontend/main.jsx`、`frontend/discussion.css`：等待確認時，討論工具列顯示「確認送出」「取消」；狀態文字「主理人整理任務書」「等待你確認任務書」。
- `src/conversation-controller.mjs`：等待確認的聊天室在側欄計入「待確認」，切到別的聊天室也看得到。
- 同批：API 參與者每次讀資料前寫的文字改為分段顯示，不再黏成一大段（`src/discussion-api.mjs`）。

## 驗證

- 既有討論測試改為任務書格式，並在共用準備程式中於任務書出現後自動確認，以繼續驗證後續流程；平行比較「不得帶入原模型答案」的檢查維持原強度。
- 新增 `test/discussion-controller.test.mjs`：確認前只開啟主理人、不詢問參與者，等待中補充被擋，確認後參與者收到任務書；取消時沒有任何參與者被開啟或詢問；等待中重啟讀回為未送出且不重新開啟。`test/discussion-api.test.mjs`：讀資料前文字分段。
- 介面實測 `discussion-ui-probe`：任務書顯示、確認前沒有參與者被詢問，按「確認送出」後完成；`discussion-speaker-ui-probe` 同步加入確認步驟。
- 補測：遠端（手機）可呼叫確認；聊天室層級不自動確認時，側欄顯示待確認、補充與插話被擋、確認或取消後解除；介面實測實際按過「取消」且沒有參與者被詢問。

## 限制與後續

- 主理人讀不到本機檔案。要讓參與者看到某個檔案（例如官網 `index.html`），請在發起討論時附上該檔案，或提供網址讓主理人讀網頁。是否讓主理人可唯讀本機檔案，涉及 10-08 討論模式「原生工作階段不開本機讀寫工具」的設計與權限，需本人另行決定。
- 等待確認沒有時限；主理人工作階段在等待期間保持開啟（若主理人是 Gemini，期間佔用帳號租用，其他 Gemini 工作不能換帳號）。側欄的「待確認」提示讓本人看得見。
