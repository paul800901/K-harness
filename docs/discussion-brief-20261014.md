# 多模型討論改由主模型依本人指示發起（2026-10-14）

## 起因

一場交叉審查（請各模型評論 Gemini 對官網首頁的意見）先因 HTTP 400 失敗，重跑後雖成功，但各模型花大量力氣自行翻找工作區、比對網站版本。本人指出：「網頁本體不是讓他們自己去查」。原本的流程是本人直接在討論模式按送出，K 把原文加上整個工作區（約 3 萬個檔案）的讀取權交給參與者，並要求 API 參與者「自主列檔、搜尋」，參與者只好自己找材料。

## 設計經過

1. 先做了「由主理人另開工作階段整理任務書，本人按確認才送出」的版本（提交 b120def、3f265f3，未部署）。Fable 第二審指出關鍵限制：討論模式的原生工作階段自 10-08 起就不開本機讀寫工具，主理人讀不到本機檔案，只能讀網頁，可能憑記憶補寫檔案內容。
2. 本人提出更好的設計：「討論那邊是一個設定……按下去並不是開始討論，而是設定好討論的設定。接下來在一般對話裡跟 AI 講完，跟他說我要做討論，討論的設定就注入了，就像 skill 一樣，然後開始進入原本的討論模式。」
3. 本人決定：主模型依指示發起時**直接開始**（不再另按確認）；最後整理**維持列出各家意見、不當裁判**，需要統整時再請主模型做。

## 現行做法

- **設定**：輸入框上方選擇討論模式與參與者，只是設定；按送出照常把訊息交給聊天室的主模型。
- **像技能一樣注入**：選了討論模式時，K 在本人訊息後附上一段說明（`src/conversation-controller.mjs` 的 `discussionNote`）：目前設定的模式與參與者、任務書要包含的內容（目的、要做的事、材料——主模型可讀本機檔案與網頁並引用原文、範圍、未知；平行比較不得放入任何模型的答案或立場），以及「若本人在這則訊息要求開始討論，回覆最後加上 `k-discussion` 開始標記；否則照常回答、不加標記」。畫面上只顯示本人原文（沿用討論交接的顯示對照）。設定無效（例如模型不在清單）時，訊息在送出前就被擋下。
- **開始**：只檢查**附了設定送出的那一輪**。這一輪結束時，若回覆以開始標記結尾，K 以標記前的全文為任務書開始討論；沒有標記就只是一般回答。檢查只在本次執行中進行，K 重啟或後續沒附設定的回合即使出現標記也不會開始，不會從歷史復活討論。開始不了（例如還有排隊訊息、子代理未結束）時，在聊天室上方顯示「討論未開始：原因」，送出下一則訊息時清除。
- **討論本身**：任務書以「討論任務書」顯示，交給每位參與者（材料欄位 `brief`），主持人（同一主模型的討論工作階段）第一次安排發言時也收到任務書；之後的安排、插話、停止、最後整理與交接照舊。原本的「主理人另開工作階段整理背景」與「等待確認」均移除。
- **參與者範圍**：參與者提示與 API 系統指示改為以任務書為主要材料，需要核對時才讀指定或相關的原文，不要列出或搜尋整個工作區。
- **介面**：主模型回覆最後的開始標記顯示為一行「↳ 依此任務書開始討論」；設定面板說明改為「設定好後照常跟主模型對話；要開始時告訴它『開始討論』」。移除「被審查內容」欄位（由任務書承載）。`/api/discussion/start` 不再對外開放（含手機遠端），討論只能經主模型發起；插話與停止照舊。

## 同批其他修改

## 限制

- 是否開始取決於主模型在回覆最後正確加上標記；漏加或格式不符時就不會開始（不會誤開），本人可再說一次。
- 附加說明會出現在主模型的原生對話歷史中（模型看得到，本人畫面不顯示）。
