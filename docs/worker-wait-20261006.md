# 主代理待命、子代理活動與關閉失敗恢復

## 需求與根因

使用者要求等待子代理時不要讓 Luna 為了查進度空轉，但介面要看得到尚未回報的子代理、是否久無活動、失敗與未知。另要求將先前未部署的 `76e8fa2`（受阻恢復、GPT 原生 Fast、子代理明細）與 `f77fdb4`（長細節收合）一起更新。

舊畫面底部只在主代理 `busy` 時顯示；主回合結束後，仍有工人也看不到等待狀態。工人紀錄原本多數沒有活動時間，無法辨識執行狀態與內容回報的新鮮度。主代理結束一個回合並不等於整項工作完成，也不該為了畫面保持「執行中」而持續啟動模型。

另一項已觀察錯誤：正式啟動器 16:37:51 關閉失敗，16:37:57 使用者拒絕強制結束，後續無法重開；Electron 的 close catch 沒有重設 `closing`，且成功關閉前就解除畫面通知。存在背景程序本身不能證明模型仍在執行；未取得原始關閉失敗的底層原因，不把這項畫面恢復修正冒充解除所有未確認工人。

## 修改

- 主代理沒有執行回合但仍有子代理時，頂端和底部顯示「主代理待命 · 等待子代理：N 個」。按來源聊天室顯示，不將另一個聊天室的工人算成目前聊天室的等待。頂端子代理總數仍保留全域範圍。
- 子代理清單及既有工作面板顯示實際活動距今多久、等待工具、久未回報、錯誤與最後讀回時間。沿用既有五分鐘安靜門檻，只提示「是否卡住待確認」；不是自動判死，更不自動停止、改派或重送。
- Codex 子代理串流、Claude 原生子代理及 GPT/Gemini bridge 記錄真正內容/工具事件；不把查詢、用量、ping、重播或重複工具狀態當新活動。主子代理的活動時間分開。重啟後的保存資料只代表上次觀察，不冒充現存程序。
- 畫面時鐘只做本機呈現；未新增輪詢模型、排程服務或 watchdog。既有完成/失敗通知沿用原先工具結果交接，未知工作不重播，既有完成提醒仍等待主代理接回結果。原生目標是否自行繼續仍由原生核心管理，不宣稱 UI 可保證任何模型永不自行查詢。
- `settled:false` 不因 status 字樣為 failed 就被當成停止完成；計數與清單一致保留待確認。
- 安全關閉失敗後允許重開畫面；成功關閉才解除畫面通知。原本確認子代理停止的檢查不變，也沒有自動強制結束。
