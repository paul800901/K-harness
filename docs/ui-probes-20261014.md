# 介面實測整修（2026-10-14）

[K 全面檢查後續](k-audit-followups-20261014.md)發現 46 個真瀏覽器介面實測（`test/*-ui-probe.mjs`）中有 16 個長期失敗。它們不在 `npm test` 內、平常沒人跑，所以介面改動後腳本沒跟上也沒人發現。本人指示接著處理。

## 失敗原因與處理

**一、環境不一致（7 個）**：46 份腳本各自寫一段瀏覽器啟動，混用本機 Google Chrome、Edge、專案 Chromium 與寫死的版本路徑；在工作樹或沒有對應瀏覽器時就失敗，版面量測也因瀏覽器不同而不一致。手機遠端 3 個實測讀取早已不存在的 `.runtime/mobile-remote/test-key.pem`；語音實測讀取已不存在的合成音檔。

- 新增 `test/ui-probe.mjs`：統一以專案已授權安裝的 `.runtime/playwright-browsers` Chromium 啟動（工作樹會往上找到主工作樹那份），不寫死版本號。
- 46 份腳本改用它（Gemini 3.8 Flash 依明確規則機械轉換，主代理逐檔檢查差異：沒有殘留舊啟動、沒有動到任何斷言）。
- 手機遠端 3 個實測改為每次以 Git 附帶的 openssl 在暫存區產生一次性自簽憑證，跑完即清除；不保存、不搬移任何既有金鑰。
- 語音實測改為每次以 Windows 內建的臺灣中文（zh-TW）語音合成含「語音」的句子（本機為 Hanhan），交給本機 Whisper 辨識；合成失敗會顯示原因。

**二、清理來源**：45 份腳本預設把截圖與結果寫進 `.runtime/<帶日期名稱>`，正是先前整理時 `.runtime` 根層雜物的來源。改為預設寫入 `test/scratch.mjs` 的自動清理暫存區；需要為工程紀錄保留時，設定 `K_UI_EVIDENCE_DIR`（原本個別腳本的輸出路徑環境變數照舊有效）。`attachment-label` 原本預設讀取一份早已不存在的舊建置，改為讀取正常的 `dist-ui`。

**三、腳本跟不上已記錄的介面決定（8 個）**，只更新預期，不改產品：

| 實測 | 過時之處 | 依據 |
|---|---|---|
| gpt-flash | 子代理選單順序；假目錄的 Flash 沒列推理程度 | 10-08 子代理改依原生目錄、GPT／Claude／Gemini 分組；推理程度依原生清單 |
| model-picker | 新對話子代理預設 | AGENTS 第五節：預設「AI 自動選擇」 |

| model-picker-compact | 「登入 Gemini 訂閱」按鈕（改為檢查「新增 Gemini 帳號」三種登入狀態下皆可按；假資料補上多帳號功能已啟用）；過期額度標「舊」 | 10-03 改為直接新增 Gemini 帳號；10-07 過期額度改標「目前額度待查詢」 |

**四、已知退化（2 個，待本人決定）**：`queue-edit` 與 `process-details` 在 900×700 視窗加 150% 介面放大（約 600×470 可用）時失敗：編輯排隊訊息時送出鈕被推出畫面，或聊天內容只剩約 76 像素高。這**不是本來就放不下**：`docs/queue-edit-20261005.md` 與 `docs/process-details-20261006.md` 記載此尺寸當時通過（前者還是特別限制待送區高度後才通過）。待送區高度上限仍在，擠掉空間的是頂部：麵包屑、「目標／壓縮次數／子代理」狀態列、側欄開關與「一般對話」模式選單在窄畫面各占一行，頂部約 290 像素。推測來自 10-08 的 c5d605d（聊天室活動快覽）與 10-08／10-09 的 a693ba4、421c360（討論模式選單），未逐一建置確認。是否在窄畫面重新安排頂部屬於介面設計決定，交本人決定。

**本人決定（2026-10-14）：暫不修。** 原話：「應該是不會啦，頂多應該就125啦，150是當初為了攏魚所以弄出來的。」日常最多使用 125%，該尺寸正常；兩個情境保留為已知退化照跑照報，日後若版面調整順帶修好即刪除清單項目。

**後續：** 本人隨後決定直接移除 150% 縮放選項，兩個情境與已知退化清單一併刪除，見[移除 150% 介面縮放](remove-scale-150-20261014.md)。

兩個實測仍保留此情境：照跑、截圖、印出 `KNOWN REGRESSION`，但不讓整批失敗；`test/ui-probe.mjs` 的已知退化清單只有這一項，修好後刪除即恢復為一般檢查。另加 900×700／125% 與 1100×760／150% 兩組照常檢查。（最初版本曾把這兩個情境改成其他尺寸、稱為已知限制；Fable 第二審指出那會讓退化從此不再被發現，已更正。）

## 防止再次老化

- 新增 `npm run test:ui`（`scripts/run-ui-probes.mjs`）：依序跑完全部介面實測（各實測使用固定連接埠，不並行）並列出結果與已知退化；可帶名稱片段只跑部分，例如 `npm run test:ui -- usage`。需先 `npm run build:ui`。實測逾時會標明「逾時或被中止」：被中止的實測來不及收尾，請確認沒有殘留的 node／chrome 程序占住固定連接埠。
- `test/ui-probe.mjs` 會檢查 Playwright 確實使用專案 Chromium；實測若在它之前就載入 Playwright，會直接報錯，不會默默改用別的瀏覽器。
- 發布流程中介面有改動時，加跑 `npm run test:ui`（AGENTS 第二節）。

## 驗證

- 修改前：46 個中 29 個通過。統一啟動與產生測試資料後 36 個通過；處理上表後全部 46 個通過（其中兩個各含一組已知退化情境，照跑並列出）。
- `npm test` 不受影響（本批只改測試腳本、測試工具與 package.json 指令）。
