# 圓桌面板：按鈕要看得出是按鈕（2026-10-27）

## 起因

本人看右側「圓桌」多人討論面板時指出：按鈕看起來只是一行文字，「如果不是設計者，誰知道那裡能按？每次都要猜，太蠢了」。本人明確表示這是最在意的人機功效點；其他美化交給 AI 判斷，「改完看看狀況」。

根因：全站 `button` 預設透明、無框（`frontend/style.css` 第 9 行），只有 hover 才有底色。圓桌裡「停止討論」「補充給此人」「閱讀整理全文／任務書」、聊天區「開啟圓桌」、手機版切換參與者的色點，平常都像純文字或裝飾。

## 討論

Opus 5.5（主代理）先提六點，交 Gemini 3.8 Flash（high，唯讀）從審美與易用性挑戰。結論：

- 採納 Flash：不做「回覆中」呼吸動畫（多個模型同時回覆會一起閃，干擾主工作區）；「看全文」提示不和「補充給此人」擠在同一角；卡片標題整合；主持人卡片與參與者區分；未產生整理時整理區塊縮小；窄版摘要 5 行改 3 行；按鈕不上彩色，顏色只留給身分與狀態。
- 折衷：「停止討論」Flash 主張平常灰、hover 才紅；主代理認為會中斷工作的按鈕平常就要可辨，而它只在討論進行中才出現。採外框同一般按鈕、文字紅色，hover 才出淡紅底。
- 不採：批次分隔列（會改變表格列結構，現有實測依列數檢查；改把批次留在卡片標題列）。

## 修改

只動圓桌自己的元件與樣式，沿用既有 `.primary`／`.secondary`／`.danger`，不另造設計系統、不新增按鈕或功能，不影響 K 其他地方的按鈕。

- `frontend/discussion-roundtable.jsx`
  - 「開啟圓桌」套 `.primary`（實心深底）。
  - 「停止討論」「閱讀整理全文」「閱讀任務書」、閱讀導覽（回到格子／上一位／下一位／上一批／下一批）、手機版全文標題鈕套 `.secondary`。
  - 「補充給此人」改膠囊次要按鈕，文字「＋ 補充給此人」（寬版表頭、窄版卡片、手機三處）。
  - 手機版參與者切換色點套 `.secondary`，成為有框的小按鈕。
  - 卡片標題列：批次與狀態同一行；狀態改帶色點的靜態標籤（回覆中／等待＝黃銅、已完成＝綠、額度用完＝紅、其他＝灰）；卡片底部「看全文 ›」。
  - 主持人格子加 `discussion-roundtable-host`；參與者格子帶座位色變數 `--seat`。
  - 尚未產生整理時，只顯示一行淡色「尚未產生整理。」與「閱讀任務書」；有整理才顯示「閱讀整理全文」（原本點開只會看到同一句「尚未產生整理。」）。
- `frontend/discussion-roundtable.css`
  - 圓桌內 `.secondary` 加淡陰影與 hover 加深外框；`.secondary.danger` 紅字、hover 淡紅底。
  - 參與者格子左側 3px 座位色條（寬、窄版都有），主持人格子淡灰底。
  - 窄版卡片摘要 3 行；手機版「補充給此人」不撐滿整列、維持 44px 觸控高度；參與者切換鈕間距。
