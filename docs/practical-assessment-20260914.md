## 主要品質發現

### Flash A

- 原文「Sol 尚未驗證」被寫成「Sol 未接入」，把未知升格成確定未具備。
- 原文「續跑指令尚未實作、壓縮與重啟後記憶表現尚未驗證」被合併成「續作與記憶未實作」。
- 引句雖存在，若干章節／驗證批次歸屬不準。逐字搜尋通過不等於引用結論正確。
- 交接限制未直接明列目前通用非臨床範圍。

### Flash B

- 四個 MCP 工具 schema、同 ID 去重、wait 逾時不取消、EOF 收尾及 completed 不等於驗收等核心流程正確。
- 把「跨目錄存取」一概列為不允許；實際可讀寫工作區內明確授權的相對子路徑。
- 漏寫輸出父目錄必須已存在；輸出同樣受 256 KiB 限制僅留在引文，操作說明不夠明確。
- 對完全未知 ID 描述為讀記錄並等待；實際 inspect 會報錯，沒有可等待的已知工作。
- 「completed 才有 output」不精確：其他狀態也可能回傳空字串欄位；正常 completed 才填入非空最終回答。
- 一個帶引號程式片段被截短而未標示節錄。另一處只是空白壓縮，不算實質品質失敗。

### Luna 同題對照

最終版本較短，核心流程大致正確，也沒有 Flash 的「一律不能跨目錄」斷言；但仍漏寫範例的輸出父目錄須存在、來源已存在等前置條件。把 cancel 接成必然寫入 cancelled 也不夠精確：取消只是請求；若工作已正常完成，completed 仍可保留。不得以不同模型替代主代理驗收。原稿及自身縮寫過程的限制保留，不假稱一次交付無修訂。

## 讀寫及用量證據

App 原始紀錄確認 Flash A、B 分別 start／wait 各一次，無重派。原主代理另讀兩份 job.json、Pi 原始訊息和實際檔案，確認所有六個授權輸入讀取與目前原文一致（A 一份、B 五份），八次工具呼叫均無錯誤，輸出逐字等於 Flash 的 write_output 內容。程式、AGENTS、測試時的 README 及全域設定在測試期間均未變。

兩工作 Pi 保存的用量合計：未快取輸入 14,139、快取讀取 30,720、快取寫入 0、輸出 15,613，總數 60,472 tokens。reasoning 9,825 已包含在輸出中，不能再加一次。欄位解釋由本機固定版本 pi-ai 的 `parseChunkUsage` 核對：input 為 prompt 減去 cacheRead/cacheWrite，output 取 completion_tokens。

請求別名為 `deepseek-v4-flash`，Pi 實際訊息的 responseModel 為 `deepseek-flash`；不据此宣稱精確實體版本。上述不是 DeepSeek 實際帳單，也不是 Astra 訂閱消耗。未取得主代理可歸因的訂閱用量、Luna 同題 token 或帳單，因此沒有套餐節省比例結論。

## 採用範圍與下一個工程方向

先讓 Flash 處理規格清楚、原始輸入固定、能快速核對的非敏感抽取／格式轉換／文件初稿。涉及「現況是否成立」、架構判斷、重要操作邊界和正式交接，仍由 Astra 決策並驗收。不要為極小工作增加一層派工，也不要在日常流程複製本次為蒐集證據而採用的雙層 Astra 複核。

若繼續工程，優先改善一個主控直接派工與一次有針對性的驗收，讓成果交接清楚區分確定／未知、附可定位來源，並用實際修訂後的完整時間決定擴大範圍。沒有新失敗證據前，不新增記憶框架、常駐服務或廣泛工具權限。這是方向判斷，不表示本輪已修改提示、模型預設或產品路由。

接入仍沿用 [官方文件所載的專案範圍 MCP](https://learn.chatgpt.com/zh-Hant/docs/extend/mcp)，沒有更改全域模型或計費路徑。
