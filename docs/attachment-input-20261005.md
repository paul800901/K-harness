# 附件顯示、份數及執行中補件修正（2026-10-05）

## 使用者可觀察的要求
- 聊天泡泡只呈現本人輸入的文字；附件以檔名卡片呈現，不展開 `K_ATTACHMENT_CONTEXT`、路徑或 JSON。
- 8 份是 K 自訂限制，沒有查到三家核心共同必須限制為 8 的依據；移除 K 的每則份數上限，不宣稱原廠無限量。
- 本人後續指出留下單檔 8 MB 同樣違反「依原生核心」方向：移除 K 自訂的單檔、文字量與 PDF 頁數容量門檻，不改成另一個任意固定數字；不是保證所有核心／格式／電腦均可處理無限大的附件。
- 已接通的 GPT／Claude 即時引導也應能帶附件；Gemini 現有 headless 接法仍不支援執行中引導，不改用重播／停止重開假冒。
- 不修改使用者附件、不讀案例資料、不打斷正式工作；原生歷史與模型收到的資料保持完整。

## 根因與修改
- `src/desktop-controller.mjs`：原生 `item/started` 把本機使用者訊息轉為 native 後，`item/completed` 不再認得它，將原始模型輸入（含 K 產生的附件 JSON）覆蓋顯示文字。現在按原生 ID／完整輸入比對保留顯示投影，送出回覆也沿用已轉換的訊息 ID，避免確認順序造成重複泡泡。
- Codex 的一般送出與 `turn/steer` 共用原有附件輸入格式，傳文字／檔案參考及 `localImage`；仍驗證來源對話、模型圖片能力與原生回合 ID。重新開啟歷史不再卡在 8 份，個別附件讀回失敗保留警告而不外露內部 JSON，不修改原生歷史。
- `src/claude-controller.mjs`：一般送出與即時引導共用原有附件組裝，保留文字預覽／完整路徑及原生 image block。讀取期間回合結束／切換不送往別的工作；原生確認與失敗不重送語意不變。
- `src/input-queue.mjs`：傳遞完整附件 ID，而非即時送入只傳文字；不支援引導的核心仍保留排隊。移除份數檢查，保留格式、狀態、持久化與不明送出不重播。
- `src/gemini-controller.mjs`、`frontend/main.jsx`：第一階段移除 K 自訂 8 份檢查，當時留下大小與頁數；容量門檻已在下方追加補修移除。內容型態、來源對話等必要檢查保留。
- `frontend/queued-messages.jsx`：有附件不再一律停用「立即送入」，依核心能力及排隊狀態呈現。

## 追加補修：移除 K 自訂附件容量門檻

### 判斷與改動
- 前一輪把要求縮為「份數」，留下 8 MiB，是範圍解讀過窄，不是三家核心已確認必須如此。官方 Codex App Server 提供 `localImage` 及文字輸入，Claude 與 Gemini 接頭的文件／影像／原始多模態走不同路徑；未查到可將所有檔案統一設成 8 MiB 的原生依據，不把 ChatGPT 網頁、Claude 網頁、Gemini API 的數字移植進 K。
- `src/desktop-files.mjs` 移除單檔 8 MiB、base64 12 MiB、純文字／擷取文字 256 KiB、PDF 60 頁，以及讀取／下載 8 MiB 檢查。檔名、編碼、非空、UTF-8、已接通型態、PDF 格式驗證、工作區與對話歸屬照舊；不改原檔或偷偷截斷內容。
- `src/desktop-server.mjs` 移除附件 upload 的 12 MiB JSON 門檻，改成累積原始 chunks 後一次 UTF-8 解碼，避免大請求反覆複製／掃描全文；認證／同源／明確本機請求檢查仍在讀本文之前，其他命令與語音請求原限制不動。
- `frontend/main.jsx` 不再因單檔大於 8 MiB 擋下；說明與 README 一併改正。人類文字預覽仍只顯示前 256 KiB 並標示節錄，完整原檔可下載；這是顯示取捨，不是附件容量限制。
- 沿用現有原生傳遞：GPT 讀工作區附件路徑／localImage，Claude 使用原生 image block／文字預覽加完整路徑，Gemini 使用原始檔案路徑。原生超限或讀檔拒絕照實回報，不拆檔重播、換模型／帳號或另一計費路徑。

### 驗證與限制
- 完整來源測試 **766/766**、建置成功。10 MiB 以上假文字檔透過真 HTTP 上傳（base64 本文超過原 12 MiB）、儲存原檔、完整擷取、節錄預覽與完整下載均通過逐位元組讀回；未登入、跨來源、跨對話仍拒絕，其他命令本文限制仍有效。
