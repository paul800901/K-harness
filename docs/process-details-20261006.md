# 長處理細節的收合入口與捲動

## 需求與根因

使用者點開處理細節後，大量工具輸出將唯一收合入口推到畫面上方，難以收回。舊 K 只限制每筆 pre 的高度，整個細節區仍無上限。

本機 DSH 的思考／壓縮摘要採吸頂收合標題，工具輸出另有限高；只讀參考，不修改 DSH。K 採最小組合：整段細節使用一個限高捲動區，收合標題固定在聊天捲動區上緣，避免每筆輸出再套一層捲動。

## 修改

- `frontend/main.jsx`：處理過程提供明確「查看細節／收合細節」文字；滑鼠、Enter／Space 都能切換。焦點在細節內時 Escape 可收回並回到標題，不占用全域快捷鍵。收合後將同一標題以 nearest 捲回可見範圍，不跳到最早或最新回合。
- `frontend/style.css`：標題吸頂並使用不透明、隨主題的背景；整段內容最高 28rem／畫面半高（配合介面縮放），短內容自然高度。保留全部內容、換行與選字，只設一個內部捲動區，末端滾輪不帶動整個聊天。
- `test/process-details-ui-probe.mjs`：攔截全部 API、只使用假訊息；80 筆各 60 行工具輸出、長原生摘要、歷史中段、進行中追加、滑鼠／鍵盤收合、焦點、獨立展開狀態、四種尺寸／主題／縮放及三家共用呈現。

不改原始事件、後端、模型、權限或實際工作，不刪除／截斷細節，也不另建面板、快捷鍵系統或持久狀態。

## 複查觀察與限制

- Opus 提醒既有行為：工作中新增另一則助理訊息時，處理過程會移掛到新的最新訊息，展開狀態重設。主代理核對 `AssistantMessage` 確認此邏輯未在本批修改；本批追加測試涵蓋同一訊息新增工具／摘要，不宣稱修復跨訊息的閱讀狀態。它不造成收合入口消失，另留紀錄，不擴大本輪修正。
- Opus 因複查材料未列出完整背景定義而提示吸頂底色待核。主代理核對 `frontend/style.css`：聊天的 `main` 使用相同 `--k-sheet`，本批吸頂背景跟隨同一主題色，無須再新增設定或狀態。
