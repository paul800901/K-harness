## 發現與主代理覆核

1. **中低：辨識程序停止異常可能卡住 K 的正常關閉。** Opus 指出 `src/desktop-server.mjs:28,145,158` 先等待辨識關閉，再依序關閉其餘元件；若 Python 五秒內未確認結束，`src/local-dictation.mjs:178–192` 拋錯，而且 `closeLocalDictation` 會快取遭拒的 Promise，往後重試仍失敗。Astra 另讀現行來源，確認此控制流程與快取行為存在；尚未做故障注入或修改。未確認停止時不能放行下一筆的鎖仍須保留，不能直接把所有拒絕吞掉當作已安全關閉。Opus 提出的 `allSettled`／`finally` 只是待評估建議，未採用。
2. **低：可信主介面權限建議收窄。** Opus 指出 `k-trusted-owner` 沒有專用的權限 handler，與嵌入網站全部拒絕的分區不同；建議只允許 K 自己來源的音訊權限。它同時承認可信頁面有來源／導覽限制、不是任意網站可請求。這項是加固建議，不是已實測的鏡頭濫用或現有攻擊；本輪沒有更改權限處理或 Windows 隱私設定。
3. **隔離驗證缺口，不是已證實可突破：** 整個 `D:\K-harness` 登錄為工作區時，尚未在這個組合下實測隔離程序對 `trusted-runtime` 的新假檔寫入是否被拒絕。`.env.local`／vault 的讀取拒絕不能取代這項寫入測試。Opus 建議只用新假檔驗證，不動正式程式；這次未執行、未嘗試修改可信執行環境。
4. **行為與使用限制：** 切換聊天室會取消當次未完成錄音／轉錄，原草稿保留但這段錄音不會保留。真麥克風、Windows 權限互動、口音、噪音與長段準確度仍未代驗。
