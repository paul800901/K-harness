# 工作活動新鮮度與部分未知的子代理計數（2026-10-05）

## 需求與根因

使用者要求修正「長時間顯示處理中，看不出是否卡住」，並指出 AI 說七張工單 running，上方卻只有「子代理：狀態待確認」。兩者不是同一個事實來源，不能拿模型自然語言補出七個即時執行狀態。

- 原介面以 `busy` 和對話群組累計耗時呈現處理中，缺少最近原生事件時間；SSE 每 20 秒存活訊號只能證明後端連線，不是模型正在推進。
- 全 K 子代理統計原本已有獨立 `running` 數字，但前端遇到任一 `uncertain` 就完全隱藏數字。另一聊天室有未知工作也會掩蓋當前可確認的工人。
- 本次不判定真實七張工作皆健康，也不採信 AI 自述「剛恢復」為卡死／恢復證據；不停止、恢復、重播使用者的既有工作。

## 修改

- `src/work-activity.mjs` 與三家主控制器：依目前原生主回合的文字／推理、工具開始／輸出／完成與壓縮事件，記錄記憶體內的最後活動時間及階段。原生子回合、Claude replay、tool_progress 的純耗時計時、帳號／用量查詢和 UI 心跳不刷新。開始送出本身只代表等待核心回報。
- `frontend/work-status.mjs`、`.jsx`、`main.jsx`：上方與回覆下方顯示最近活動距今多久，區分等待工具／子代理、原生重連、使用者確認、斷線；5 分鐘沒有新原生活動，改為「已 … 無新活動回報」，不稱已卡死。總時間改標「已耗時」。時鐘僅局部重繪文字，不更改活動、不請求模型、不新增狀態查詢。
- `src/conversation-controller.mjs`：全聊天室既有計數保留，另計 `unconfirmed`。不明或失去連線的未結束工人不算執行中，但不遮蔽其他可確認的數字；沒有可列舉未知工人的斷線仍顯示「部分連線待確認」，不杜撰數量。完成、失敗、停止與背景命令不納入。
- `frontend/style.css`：取消工作指示點的假活動閃動、狀態可換行。實際 UI 回歸發現長表頭在小視窗會讓空聊天室置中輸入區溢出、遮住原生通知；空聊天室改安全置中並可捲動，保留通知與內容可操作。
- 測試：新增 `test/work-activity.test.mjs`、`test/work-activity-ui-probe.mjs`，三控制器及跨聊天室測試補活動來源／七執行加未知案例，既有通知／計數 UI 探針更新文字。
