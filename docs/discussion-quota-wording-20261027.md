# 討論額度受阻的狀態文字（2026-10-27）

## 問題與範圍

多人討論同批有兩位 Claude 參與者回報 session limit，另一位 GPT 參與者仍在回答。原流程會等本批全部結束、保存回答，再將整場標為受阻；實查沒有永久卡死。但畫面只寫「未完成／討論中」，直接顯示英文錯誤，無法清楚看出額度已用完與正在等誰。

本人指定只修狀態文字。這批只改前端顯示，不改討論排程、等待、停止、重送、帳號或模型，不寫回既有討論紀錄。

## 變更

- `frontend/native-notices.mjs`：抽出既有 Claude session limit 文字辨識與時間轉換，供討論畫面共用；一般原生通知的文字與判斷不變。
- `frontend/discussion-roundtable-data.mjs`：依該場本批的已記錄額度錯誤顯示「額度已用完」、官方原文的恢復時間及仍在回覆者；保留已產生的部分回答。一般回覆提到額度不會觸發，API 席位不套用訂閱額度判斷，舊場次不影響新場次。
- `frontend/discussion-roundtable.jsx`：入口卡、圓桌標頭、桌面與手機席位共用顯示結果。
- `frontend/discussion-controls.jsx`：輸入框上方的討論狀態同步顯示「部分參與者額度已用完」或「部分參與者額度已用完，討論受阻」。停止中與結果待確認仍沿用原狀態。

顯示範例：

> Opus 5.5：本時段額度已用完；20:30（臺灣時間）恢復。
> Fable 5.1：本時段額度已用完；20:30（臺灣時間）恢復。
