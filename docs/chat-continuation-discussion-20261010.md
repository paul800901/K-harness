### 採納的整合結論

1. **同供應商原生分支可省人工摘要**，K 已有底層與人類入口；仍不能宣稱原封不動搬走「所有工作狀態」。
2. **先前失敗回合不必然被丟棄**：lastTurnId 排除的是選點之後，而不是過濾全部 failed turn。此聊天室失敗後已完成兩輪轉移討論，若選最新結論，先前已保存失敗資料可能仍在複製範圍。實際 model-visible input 還須查證。
3. **goal 是否帶過、狀態是什麼，未驗證就維持未知**；不能將「未證明存在」寫成「確定不存在」。同資料夾的檔案以現況為準，不倒退或重播失敗輪的已執行副作用。
4. **分支不保證清除壓縮或治好此次串流失敗**。既有工程紀錄 `docs/compaction-count-20261005.md` 曾記分支包含之前原生壓縮，是過往實測，不是本輪 Codex0.161.0 新 fork 的實測；保存 boundary／顯示壓縮次數也不等於證明全部 input 與判斷品質。Opus 未讀该文件，仅看到主代理轉述，明確標示。
5. **「壓縮太多次損壞核心」沒有因果證據**。目前只能確定一次原生遠端壓縮失敗、另一次串流失敗；新假資料六階段成功也不足以反證原長任務問題。
6. **AI 可直接操作既有分支與排除異常是兩個需求**。不要求人另手寫交接，也不把「只有某狀態擋住才准加功能」當作否決人要求 AI 操作的理由；但此輪只討論，不先實作或恢復工作。
