## 三、必須守住的限制

- 不得把單次成功泛化：DeepSeek live 驗證自述「沒有將單一驗收擴張成通用任務已合格」；「MCP 接入驗證」記「獨立 MCP 測試成功不等於 Codex App 已連線」。Astra App 原生派工驗證本身的成果也只是該次 App 派工，不能外推到 Sol、記憶或完整產品。
- 秘密邊界：不得把 API key 放入 task 或檔案授權；工具「直接拒絕本專案 `.env.local` 作為輸入／輸出」；一般 worker「不自動搜尋憑證檔」；`node --env-file`「不等於 worker 已呼叫 API」。原全域秘密檔應保留，不得搬移其他帳號憑證。
- 模型與計費：必須指定精確模型 ID，模型不存在時「直接報錯，不由 K 自行替換別名或 fallback」。請求別名 `deepseek-v4-flash` 與供應商回傳 `deepseek-flash` 須區分，且「不使用舊目錄價目宣稱實際費用」。
- 不混用他案狀態：本專案與 `D:\KAI`、DSH 及 CaseAgent「分開，不沿用它們的執行狀態」；DSH 僅作設計參考。信任登記「不代表把 MCP 搬到全域或變更其他專案、主模型與權限模式」。
- 目前只做通用非臨床工作：臨床資料與機密不得作為輸入或輸出；工人沒有 shell、外掛、技能、提示模板或 context files，也不自行搜尋憑證檔。
