# 長工作：程式觀察、事件等待與必要介入

## 使用者要求與界線

承接 `b6a6a0d` 移除 Gemini 固定十分鐘工作截止的修正。使用者要求參考原生與開源 harness，讓主代理不必短間隔輪詢，同時可查明長工時子代理是否有問題；本輪明確同意實作。沉默不能證明卡死，查詢／等待期限不能變成工人生命週期限制。

## 採用的現有做法

- DSH 本機 `continuation-activation.ts` 的 completion／inbox 事件等待：沒有工作時等待事件，不靠模型重複提問。只讀參考，未修改 DSH。
- Codex app-server 的原生工作事件及 thread/read：活動與讀回分開；原生子代理通知仍由原核心處理，不由 K 再造第二套子代理核心。[官方介面](https://developers.openai.com/codex/app-server/)
- Claude Code SDK 的 task_progress、task_notification、background_tasks_changed：有使用量增量才算新進展；背景清單是 live snapshot，消失不等於結果成功，不啟用需模型生成的 progress summary。[官方型別](https://code.claude.com/docs/en/agent-sdk/typescript)
- Goose Summon 的 peek／wait 分離：等待呼叫期限屆滿可以回到呼叫端，但不因此取消仍在執行的工作。[原始碼](https://github.com/block/goose)

這些是接法的參考，不聲稱所有 harness 都沒有執行期限，也不聲稱可從無回報證明遠端模型仍健康。

## 最小實作

- `src/worker-watch.mjs`：只觀察本次 K bridge 擁有的工人。自最後真正活動／開始後五分鐘未有進展，程式讀回一次；之後持續安靜時每五分鐘只做程式查詢，不發起模型推論。不是新服務，不啟另一個監工模型。
- 跨核心 gateway 的 GPT／Gemini 工人共用：GPT 查原生 thread/read；Gemini 查 K 持有的原 agy run。後者只是本機執行尚未結束，不冒稱有遠端健康心跳。查詢時間不更新最後活動，不自動停止、重派、換帳號或模型。
- 同一工單的單純安靜只通知主代理一次，即使中途恢復活動、又執行另一個長命令，也不重複喚醒。只有新工具錯誤／權限拒絕或查詢轉為無法確認才產生不同通知；沿用主對話既有持久去重，不另建服務。核准等待不另發安靜警告，最後一個核准決定重新起算安靜時間；完成回報仍獨立保留。
- 主代理忙碌時先排隊；恢復活動會撤掉尚未投遞的過期警告。停止／切換不送舊通知；不確定已送出的通知不自動重送。人與 AI 的明確停止路徑維持不變。
- luna_wait／gemini_wait 改成事件等待，移除每秒 thread/read；等待到期只回傳快照，原工人繼續。读回與完成競態以原生活動版本保護，晚到的舊 running 不蓋掉新完成。
- 既有 inspect 回傳最後活動、階段／最近工具、最後查詢、核准等待、錯誤、安靜檢查及已知部分成果參考；部分輸出最多 1,000 字元，完整長結果仍留工作區。結果未知或檔案清單空白不是零成果，不新增掃描所有工作區的服務。
- Gemini 執行中即提供原生工具錯誤，不必等終態才看得到。Claude 原生背景工作補讀官方 progress／全量背景清單；沒有完成事件只標待確認，不把清單消失當完成、不重複原生喚醒。
- 子代理明細沿用原入口，增加最近工具及程式檢查原因／時間，不新增管理面板或自動重試設定。

## 驗證與限制

- 定向 195/195、首輪完整 880/880 通過（後續測試數與 Opus 複查另補）。包括 wait 到期不取消、無每秒輪詢、同一警告只喚醒一次、後續完成仍通知、活動撤回警告、晚到 running 不覆蓋完成、Claude 背景消失不假完成。
- 真正 Flash 原生唯讀假資料短回合完成；觀察探針將安靜檢查縮短至一秒以驗證路徑，正式仍為五分鐘，原生 print-timeout=0s、只啟一個模型回合、沒有 skip／換帳號／小說操作。UI／最終回歸及 Opus 複查收尾另記。
- 不將假時鐘推進當成真實跑滿一天，不聲稱小說稿件已完成或可恢復尚未存檔的原生模型內容。既有 stdout 大小副本中止已移除，stderr 保護及原生失敗仍存在。
- 原生 Gemini 無可驗證的遠端健康訊號時仍只能保持不確定，交由主代理讀回原工單與實際成果後判斷；不因存在 PID 或已經過時間宣稱健康或死亡。
- 本次沒有修改正式小說、目標、登入、權限、計費或 DSH。Codex／Claude 原生子代理仍依原核心完成事件，不額外複製原生調度；K 新觀察器針對 bridge 管理的跨核心工人。
- 本機候選實作中，尚未部署／推送；本人已回覆離開並停止 K，可在驗收通過後套用，仍在實際套用前再查。
