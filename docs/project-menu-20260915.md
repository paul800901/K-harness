# 專案管理與封存入口

## 行為

- 工作區右側同一排：搜尋對話、檢視選項、新增工作區、已封存。封存入口不再獨占一整列。
- 專案旁的「⋯」提供重新命名、釘選／取消釘選、封存專案。
- 專案名稱為顯示名稱，資料夾路徑與內容不變。
- 封存專案從一般清單隱藏，也隱藏其底下的聊天；不改寫個別聊天的封存狀態。
- 已封存視窗保留封存聊天的開啟與還原，另提供封存專案的還原。
- 專案狀態保存於既有 `.runtime/projects.json`，同時接受原有純路徑項目。更新採與新增相同的序列化寫入，避免兩個視窗相互覆蓋。

## 驗證

後續修正：原生 details 選單缺少點外面與 Escape 收起行為。專案／對話三點選單現共用收起處理，點外面、焦點移出、Escape、選擇項目均會關閉，同時僅開一個。已於正式 K 瀏覽器實測點空白收起、Escape 收起且焦點返回、從專案選單切到對話選單、選擇重新命名再取消後無殘留選單；未儲存或更動正式資料。前端建置通過。

專案測試涵蓋舊清單相容、名稱／釘選／封存／還原讀回、並行新增與更新、資料夾及聊天不受更動、無效輸入、HTTP 同源與本機授權。

本輪共 35 項相關測試通過，UI 建置完成。隔離瀏覽器實測專案重新命名、釘選排序、封存、從第四個圖示還原，以及開啟封存聊天後讀取原內容；工作區封存與還原均保留個別聊天封存狀態。

正式 K 後端已載入新入口，瀏覽器從第四個圖示讀回原有兩筆封存聊天。正式資料仍為 17 筆聊天、2 筆封存，對話中繼資料與更新前一致。未對正式專案執行測試性改名、釘選或封存。
