# 待送／插隊訊息編輯（2026-10-05）

## 根因與改變

使用者指出待送訊息只有「立即送入／取消」，無法修改。原本前端與 input queue 均未提供編輯操作。

- 待送列新增「編輯」；就地修改文字、「儲存」或「取消編輯」，不覆蓋主輸入框草稿。
- 開始編輯先由後端保留該列，避免主工作剛好完成時把正在編輯的舊文送出。儲存後保留原 ID、原排隊位置及附件；取消只放棄修改，不刪除訊息。
- 編輯中的首列不自動派送，也不讓後面的列跳過它；使用者仍可明確把其他待送列「立即送入」。沒有中斷主工作或停止子代理。
- 只有未送出的訊息可編輯。正在送入、送出未確認、已送出的訊息不改寫、不重播；未知狀態仍沿用既有查明／移除紀錄規則。
- 編輯保留狀態與原文存在既有佇列檔；重開後仍保留，沿用既有重開暫停規則。未儲存的編輯文字依聊天室／列 ID 留在該視窗 sessionStorage，切去別間再回來可繼續；不是跨視窗／完整退出瀏覽器的未儲存草稿備份。
- 儲存期間暫鎖該列，成功落盤前不能派送，對介面仍呈現最後已保存狀態，避免其他串流更新提早關閉編輯器並清掉草稿；儲存失敗保留原內容及編輯狀態。既有停止造成的佇列暫停不會被儲存或取消編輯解除。
- 待送區限制高度、內部捲動；大縮放下不因展開編輯器把主輸入框按鈕擠出視窗。
