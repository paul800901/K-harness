## 需要處理的問題

### 1. 兩家 CLI 內建的帳號連接器不經過 K 的隔離（中，需要使用者決定）

- **Codex**：候選版 Codex 自己列出的工具裡，有 5 個 `codex_apps`（ChatGPT 帳號連接器）的 Figma 工具：`figma_add_code_connect_map`、`figma_send_code_connect_mappings`、`figma_weave_get_tool_inputs`、`figma_weave_list_tools`、`figma_weave_run_tool`。當時只篩出名稱或說明含「browser」的工具，所以完整清單可能更多。
- **Claude**：本對話就是正式 K 裡的 Claude 工作階段，而我的可用工具中出現了 claude.ai 的 Google Drive 和 Claude Docs 連接器。候選版登入的是同一個 claude.ai 帳號，很可能也有這些工具，但還沒驗證。
- **K 沒有控管**：K 的 `src/` 沒有任何關閉或限制這些連接器的設定，Luna 的 Codex 設定也沒有。
- **影響**：
  - 這些連接器透過 OpenAI／Anthropic 的伺服器存取第三方帳號的資料，不經過 K 的瀏覽器閘道和人工接手鎖，也不受 Sandboxie／WFP 的網路限制。
  - 這輪沒有用到連接器，所以「沒有外站存取」對這輪的操作成立。但「隔離候選」和「不登入其他網站」的說法沒有涵蓋這條通道。
- **建議**：
  - 由使用者決定保留或關閉。
    - 保留：連接器屬於給 AI 用的能力，符合「AI 操作優先」，但要寫進紀錄，並確認在略過權限以外的模式下，呼叫連接器會經過原生核准。
    - 關閉：請 Astra 查兩家官方的關閉方式，並用實際的工具清單驗證已經關閉。
  - 在使用者決定之前，隔離候選先把連接器列為「未納入驗收」，紀錄裡也補上這條通道。

### 2. Codex 是透過內建的 `exec` 呼叫瀏覽器工具（低～中）

- Codex 每次呼叫瀏覽器工具，都是先用內建的 `exec` 執行一段 JavaScript，再由那段程式呼叫 `tools.mcp__k_browser__*`。它也用 `exec` 列出了 `ALL_TOOLS`。
- `exec` 本身執行時沒有跳出核准，核准只發生在程式裡的 MCP 呼叫。
- 紀錄寫「沒有 shell」是對的，但「原生命令執行未驗收」應該寫得更精確：Codex 的原生程式執行路徑（`exec`）已經在外層沙箱裡實際跑過；尚未驗證的是 `exec` 本身能做哪些事、受哪一層沙箱限制，以及 shell 命令。

### 3. 右側畫面、人工輸入和核准的證據沒有保存（低）

- **截圖**：紀錄說主代理看過 1440×900 的全頁截圖，但證據目錄和候選版的 `browser-output/` 都找不到截圖；`browser-output/` 裡只有頁面 YAML 和主控台紀錄。
- **人工輸入**：
  - 紀錄沒寫清楚「人工」輸入是使用者本人操作的，還是主代理操作 K 右側介面模擬的，也找不到含 `HUMAN_*` 字串的操作腳本。
  - 模型讀回的值只能證明接手期間欄位被改過，不能證明輸入真的走了右側介面。
- **核准**：表格中的核准提示沒有匯出成證據。從時間來看是合理的：Codex 的 navigate 和 evaluate 分別等了 16 秒和 20 秒，snapshot 則是 0.0 秒。
- **建議**：下一輪請保存右側截圖、接手操作紀錄（寫明由誰操作），以及核准的請求和回應事件。

### 4. 「AI 調整尺寸」的現況寫得比實際保守（低）

- Playwright MCP 原生的 `browser_resize` 已經在兩家拿到的瀏覽器工具清單裡（Codex 的工具列舉看得到），所以 AI 現在就能改變頁面尺寸，視模式可能需要核准。
- 還沒做的是 K 這一側：
  - 右側畫面只依寬度等比例縮放（`width:100%`、`height:auto`），不會依高度貼合面板。
  - 右側點擊是用截圖的實際像素換算座標，理論上會跟著尺寸改變，但還沒驗證。
  - 沒有縮放（zoom）工具。
- **建議**：紀錄改寫為「底層 `browser_resize` 已開放但未驗證；縮放和右側完整貼合尚未實作」。
