# 主聊天框貼上後游標跳尾修正

## 使用者觀察
- 貼上一段中文，把游標移到段首，再輸入中文，游標跳到最後，後續文字接到文末。
- 範圍是主聊天框，不是右側瀏覽器。

## 根因與最小修正
- `frontend/main.jsx` 的 composer 訂閱在輸入元件同步受控文字的同一呼叫堆疊內，直接更新父層 `draftText`。這會打斷受控輸入值與游標的同步。
- 先移除重複 `onChange -> setDraftText`，重測仍失敗，因此不能只以該項作為根因或修復證據。
- 保留原有 composer 訂閱與草稿保存，將父層 `setDraftText` 延至 microtask；退出／切換對話後不套用已排程的舊訂閱更新。不修改上游套件、不靠強制把游標移到某處掩蓋問題。

## 隔離 UI 修前／修後讀回
使用本機假對話 `http://127.0.0.1:47845/`，未送出訊息或呼叫模型。

測試原文共 51 個字元：
```
其實我剛剛在 K 裡面輸入中文字的時候，也有發現中文字會輸入不完全。
這是貼上後移到最前面輸入的測試。
```

| 操作 | 修前 | 修後 |
|---|---|---|
| 貼上、Ctrl+Home、輸入「你」 | 文字在開頭，但 selectionStart/end = 52，錯誤跳至尾端 | selectionStart/end = 1，正確 |
| 接續輸入「好」、右移兩字、輸入「中間」 | 未測 | 開頭為「你好其實中間我」，游標 = 6 |
| Shift+Left 兩次，輸入「替換」 | 未測 | 開頭為「你好其實替換我」，游標 = 6 |

- 最終 `npm run build:ui` 成功，保留既有 bundle 大小警告。
- 全套 `npm test`：327/327 通過；紀錄 `.runtime/composer-caret-final-tests.log`。上述游標證據來自另外實際 UI 操作，不是宣稱 327 項測試涵蓋原生輸入法。
- 限制：自動化驗證的是已提交中文字的插入、選取與游標；未操作 Windows 注音／拼音候選窗，不能宣稱原生 IME 所有組字情境已驗證。使用者重新整理後仍需確認原本輸入法情境。

## 生效與邊界
- 已重建共用 `dist-ui`；K 前端重新整理後載入新版。正式後端未重啟，未操作正式草稿或對話。
- 重新整理前建議先複製保留尚未送出的草稿。
- 正式瀏覽器開關仍不存在；瀏覽器崩潰及真實登入隔離不在此修正中宣稱解決。
