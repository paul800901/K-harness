## 1. 為什麼要改

複查時確認的問題（證據都在程式碼裡）：

- **樣式只往後疊覆蓋**：`style.css` 有 25 個規則區塊在定義或覆蓋 `.app` 欄寬；前端 CSS 共有 15 種 px 字級（9–36px）、73 種色碼；`var(--panel)` 用了 4 次（`style.css` 3 次、`sidebar.css` 1 次），但從未定義。
- **暖色主題混入冷藍**：強調色是 `#007acc`（`style.css:11`），選取列是淡藍色，輸入框焦點框寫死 `#aebae9`，`--app` 視窗標題列是青色（截圖取樣 `#cde7ed`）。
- **假按鈕與重複資訊**：空白頁三張卡片是不能點的 `<div>`；標題沒有對話名稱時會退回工作區名稱，模型名稱在標題和輸入框各出現一次；成果面板的說明和空狀態講同一件事；輸入框下方常駐操作說明。
- **明顯錯誤**：「回到最新訊息」按鈕在底部時仍以半透明顯示，又佔用 36px 版面，導致空對話也出現捲軸。

使用者決定（2026-09-25）：

1. 以使用者自己決定的 K 標誌為視覺基礎：米色紙 `#fdf6ec`、深棕墨 `#483a2d`、黃銅刻度 `#aa8537`。
2. 使用者喜歡 Claude／ChatGPT 網頁的文字顯示，字型與排版交給 Claude 判斷。這兩個網頁的中文都用系統字型（在使用者電腦上多半是微軟正黑體），好看的原因在排版，不在字型。
3. 其他細節照 Claude 判斷；實作由 Astra 負責。

### 3.2 字型

```css
--k-font: "Segoe UI Variable Text", "Segoe UI", "Microsoft JhengHei UI", "Microsoft JhengHei", "PingFang TC", "Noto Sans TC", sans-serif;
--k-font-mono: "Cascadia Code", "Cascadia Mono", Consolas, "Microsoft JhengHei UI", monospace;
```

- 英文與數字用 Windows 11 內建的 Segoe UI Variable，中文用微軟正黑體，程式碼用 Cascadia Code。已確認使用者電腦都有安裝，不需要下載。
- 移除 `Inter`。使用者電腦沒有安裝，實際上一直退回 Segoe UI。
- 使用者電腦另外裝了思源黑體（`NotoSansTC-VF.ttf`），這一輪預設不用，原因有兩個：在 1080p 螢幕上，12–14px 的字會比正黑體稍微模糊；而且使用者在 Claude、ChatGPT 看到的中文多半就是正黑體。第 0 階段的樣稿要能切換兩種字型比較。如果使用者改選思源黑體，就整套換掉（把 `"Noto Sans TC"` 移到中文字型第一位），不可兩種混用。
- 粗細只用 400 和 700。微軟正黑體只有細、標準、粗三種，500–650 對中文沒有效果：500 會顯示成標準，550 以上會顯示成粗體。只有改用思源黑體時才可以加用 500。
- 除了品牌名稱以外，不加字距（`letter-spacing`）。
- 日期、時間、百分比、數量和表格數字都用 `font-variant-numeric: tabular-nums`。
- 保留 `font-synthesis: none` 和 `<html lang="zh-Hant-TW">`。

### 3.3 字級

| 變數 | 大小／行高 | 用途 |
|---|---|---|
| `--k-text-xs` | 12px／1.5 | 日期、提示、說明、徽章、額度 |
| `--k-text-sm` | 13px／1.5 | 輸入框工具列、右側面板內文、選單說明、處理過程摘要 |
| `--k-text-md` | 14px／1.5 | 介面預設：側欄、按鈕、選單項目、標題列 |
| `--k-text-body` | `var(--k-dialogue-font-size)`／1.75 | 對話內文、輸入框文字 |
| `--k-text-lg` | 20px／1.4 | 對話框標題 |
| `--k-text-xl` | 24px／1.4 | 空白頁主標 |

- 最小字級 12px，不再使用 9–11px。
- 對話裡的 Markdown 用相對字級：h1 1.25em、h2 1.125em、h3 1em，全部 700；標題上方間距 1.4em、下方 0.5em。表格 0.875em，程式碼區塊 0.8125em。
- 對話欄和輸入框最寬 720px，16px 字級時一行大約 45 個中文字。
- 對話字級預設改成 16px：`appearance.mjs` 的 `DEFAULT_APPEARANCE.dialogueFontSize` 從 18 改成 16，最後以第 0 階段使用者確認的值為準。設定裡的 14–22 選項保留。已經儲存為 18 的值做一次性遷移：加版本標記、只遷移一次、不動其他外觀值，使用者之後仍可從設定改回。

### 3.4 間距、圓角、陰影、動態

- 間距用 4 的倍數：4、8、12、16、24、32、48。
- 圓角：
  - `--k-radius-sm` 8px：按鈕、列、欄位
  - `--k-radius-md` 12px：卡片、選單、工作紙
  - `--k-radius-lg` 16px：對話框
  - `--k-radius-xl` 20px：輸入框、使用者訊息
- 陰影（深色主題可把透明度加倍）：
  - `--k-shadow-1`：`0 1px 2px rgba(43,36,29,.05)`，用於工作紙、輸入框、卡片
  - `--k-shadow-2`：`0 8px 24px rgba(43,36,29,.08), 0 1px 2px rgba(43,36,29,.06)`，用於選單、浮出面板、↓ 按鈕
  - `--k-shadow-3`：`0 24px 64px rgba(43,36,29,.18)`，用於對話框
- 動態：時間 120–180ms、ease-out，只用在顏色、透明度和框線。「處理中」圓點用 1.6 秒的呼吸動畫。保留 `prefers-reduced-motion` 時全部關閉的規則。

### 3.5 焦點、捲軸、DSH 匯入

- 全域焦點樣式：`:focus-visible { outline: 2px solid var(--k-brass); outline-offset: 2px }`。輸入框內的文字區不畫外框，改由外框的 `:focus-within` 顯示（見 5.5）。
- 捲軸：`scrollbar-width: thin`，拇指用 25% 的 `--k-ink`（可用 `color-mix`），軌道透明，三個主題共用。
- 移除 `style.css` 開頭的兩行 DSH `@import`，原因如下：
  - `design-platform.css` 只在 `body` 定義 `--dsw-*` 變數，K 沒有任何元件使用。
  - 唯一用到這些變數的是 `scrollbar.css`，但 K 從未設定 `data-ds-dark-theme`，依程式碼推斷深色主題的捲軸會是淺色的。
