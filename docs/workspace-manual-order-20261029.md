# 工作區上下移動與電腦、手機同步（2026-10-29）

## 本人需求與原因

本人指出工作區的選單不像對話，沒有上移／下移，要求「修好它」，並補充手機也必須同步。原本只有對話 ID 的手動排序，工作區只按已登記順序及釘選狀態顯示；並非選單被遮住。

## 行為與修改

- 手動排序下，工作區選單增加「上移工作區／下移工作區」。依工作區分組與單一清單兩種檢視都可用，包含空工作區。
- 釘選工作區維持優先；只能在相同釘選狀態內上下移動，首尾與釘選邊界的按鈕停用。工作區名稱、實際資料夾與各房對話順序不因移動改變。
- 工作區使用路徑正規化識別，改名不影響排列。新工作區加在既有順序尾端，封存或暫時未出現的工作區保留原位置。切換「最近訊息」只改對話排序，已排好的工作區位置保留；切回手動仍可移動工作區。
- 沿現有 `sidebar/preferences` API、串行原子寫入與 SSE 廣播，共用同一份私人排序設定。電腦移動會同步手機，手機也可移動並同步電腦，並非兩端各存 localStorage。
- 私人 `sidebar-preferences.json` 加可選的 `projectOrder`；讀舊檔時預設空清單，不丟掉既有對話排序。發現新工作區走 `appendProjects`，舊畫面補資料不覆蓋另一端已保存的排列。壞檔仍保留原檔並顯示錯誤，不自動重建。
- 沿用既有偏好的操作語意：兩端真正同時手動改排時，最後到達的明確保存生效，未新增衝突合併系統；這與被動新增資料的 append 不同。

修改檔案：`frontend/project-groups.mjs`、`frontend/project-sidebar.jsx`、`frontend/sidebar-preferences.jsx`、`frontend/main.jsx`、`src/sidebar-preferences.mjs`，以及三份既有測試 `test/sidebar-data.test.mjs`、`test/sidebar-preferences.test.mjs`、`test/sidebar-sync-ui-probe.mjs`。不新增套件、服務、權限、帳號、付費路線或人用設定。
