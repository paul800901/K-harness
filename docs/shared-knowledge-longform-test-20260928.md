## 測法與限制

- 正式採用素材與答案表：`.runtime/shared-knowledge-r1-20260928/acceptance/longform-distributed/source.md`、`fixture.json`。主代理在呼叫模型前固定答案，不依結果改答案表。
- 6 項定案分別出現在字元位置 1,846／5,390／8,948／12,507／16,082／19,705：發布、備份、告警、驗收、回復、權限。包含條件、否決理由、提案與明確決定的區別。
- **這是人工構造的長文壓測，不是自然使用者資料集。** 周邊閱讀筆記使用重複模板與各主題背景，不能据此推廣一般長文準確率；但足以觀察單回合 6 項明確定案會不會被截成 4 項。
- Luna 的前置素材未採用：定案集中前段，後段重複備忘。主代理接回後建立均勻分布的獨立素材；舊稿原處保留。產生器曾因舊檔已存在拒絕覆寫，沒有覆蓋既有稿；真正模型呼叫只使用上述凍結稿。
- 真實來源核心為 Claude Opus 5.5；讀回為新 Claude Opus 5.5／Codex GPT-6 Luna High。每次 consumer 使用同一份來源共享文件的獨立測試副本，不沿用來源聊天室歷史，也不讓前一個答覆污染下一組。
- 首答測試明確禁止工具、重貼或重讀全文，以隔離共享注入的效果。**沒有測試允許工具後能否人工定位原文補救**；本輪不能宣稱所有按需讀檔路徑都失敗。實際工具呼叫均為 0。
- Jev 真請求只送合成 query／候選摘要；金鑰僅驗收程序載入，不交給兩家 native host 環境、不輸出到證據。不新增生產環境的 key 載入機制。

## 原始碼對得上的根因（本輪未修）

`src/shared-knowledge.mjs`：

1. 第 18 行要求 native model **Maximum four records**；第 69 行再 `items.slice(0,4)`。來源回合已理解六項，卻只有四個獨立共享條目。
2. 第 5、43 行使超過 16,000 字元的保守文字抽取直接回傳空集合。這次來源 21,625 字元，不會透過該備援擴充缺少的主題。
3. 第 168 行本地檢索只看 `subject + statement`，而輸出優先用 `sourceQuote`，沒有為缺項問題自動展開 `sourceExcerpt`。Jev 只替這些已有候選排序，不能找回沒有成為候選的兩個主題。
4. 第 117–124 行 correction／revocation 不是恰好一個同主題舊條目時，皆標 conflict，包括 **0 個**。這次 false-conflict 的原始碼與實際結果一致。

下一個必要修正應針對「長文多主題的保存／缺項回讀」及「缺少關聯不是已證實衝突」，保留來源、有限注入與首答前完成的邊界。**不應僅把數字 4 調大後，就宣稱任意長文已解決；也不應交給 Jev 分數決定丟棄哪些明確定案。** 修後用本輪相同凍結稿／問題重測，保留此次失敗證據。
