## 現況與必要接線邊界

目前 worker-policy／model-picker／gateway schema 都把 K 選單限在 Sol、Luna、Flash 三種，不是只改畫面即可。

- GPT→GPT 原生子代理已接；GPT→Flash 已走現有 K gateway。
- Claude→GPT／Flash 已走現有 gateway；Claude→Claude 原生 Agent 已被 K 記錄，但目前選單設定未完整管到該路線。原生 Agent 別名／完整 ID／effort 是否照指定，必須真回合核對；同一個「子代理」設定處理，不拆兩個人用工程設定。
- **GPT→Claude 高階子代理尚未在 K 接通，正是這次新增真用例所需路線。** 必須補現有 bridge 的 Claude 工人執行接法，沿既有工單、核准、完成通知、查詢、取消與 unknown 不重播；不另造 MCP 框架或另一套核心。Haiku／Sonnet／Opus 不能只加三個名字就交付。
- Gemini 主代理反向派 GPT／Claude 不是本次必要範圍，不因「全列」順手建立所有方向路由。
- 各路線派工權限不高於主對話。接線後需限定真回合驗證三個新 Claude 型號、結果回來源、取消／核准與不明結果不重送；動態目錄不是永久每模型探測或測試框架。
- 推理程度以實際入口及逐模型原生清單為準：Haiku 4.5 無 effort、Gemini 3.1 Pro low／high；不得因固定 enum 誤拒絕合法資料。
