# 桌面主代理直接工作驗收（2026-09-15）

## 結論

K 桌面主代理不再固定唯讀，也不必把每項操作交給 Flash。主代理可自己讀檔、修改程式、執行命令及測試；適合時才使用既有子代理路由。這次補的是桌面主控的工具與核准接線，不是整套 Codex App 功能等同宣告。

## 實作與操作

- 建立新工作及輸入框都有「操作權限」：新工作預設「工作區可修改」，也可選「唯讀」。輸入框修改於下一次送出套用；既有對話保留原權限，沒有紀錄的舊對話維持唯讀。
- 主代理使用既有 Codex 原生工具、訂閱登入及原始對話歷史。工作區外或額外存取由原生權限機制提出核准，K 不自動切到完整存取、不改全域設定、不更換計費路徑。
- 核准卡顯示命令／工作目錄、實際檔案差異或額外權限範圍。命令與檔案只做本次核准；額外權限明確標示僅本回合。拒絕、過期或停止後的請求不會暗中變成核准。
- 主代理透過原生檔案修改工具交付的工作區內檔案會加入成果面板，可預覽／下載，重開後從原始工具紀錄找回。
- 「停止工作」中止主回合、處理目前對話背景命令及已辨識的子代理；保留已寫出的檔案，不宣稱復原已發生的操作。
- 使用官方實驗性背景終端清理介面；清理回應後最多再等約 2 秒讀回程序清單。只送一次清理，不重送原始命令；未確認退出就回報狀態未確認。
- Flash 的逐任務工具／檔案授權仍獨立，不因主代理可改工作區就自動放寬。

## 真實驗收

只使用人工資料，工作區為 `.runtime/direct-work-20260915/main`。

主代理：帳號實際可用的 `gpt-5.6-terra`，推理程度 `medium`；對話 `01a0a0c2-c11a-7ef3-8c04-2c593ef72dbf`。本組沒有 Flash 或 GPT 子代理呼叫。

| 項目 | 觀察結果 |
| --- | --- |
| 自行讀改測 | 先執行 `check.mjs` 重現 77 與 230 不符；讀取三份檔案，只修正 `total.mjs` 的數量乘單價，再測成功 |
| 實際交付 | 主代理建立 `result.json`，內容為 `{"total":230,"verified":true}`；外層主代理另讀原檔及重跑測試，結果 `K_DIRECT_CHECK_OK total=230` |
| 單次寫入核准 | 唯讀模式下提出 `approval-once.txt` 的新增差異；核准前不存在，畫面核准後內容為 `K_APPROVAL_OK` |
| 拒絕 | 拒絕 `approval-denied.txt` 新增；檔案不存在，主代理回報停止且沒有重試 |
| 重開 | 重啟 K 後重開同一對話，原訊息與三項成果恢復，成果 JSON 預覽正常 |
| 停止 | 執行只輸出文字、60 秒自行結束的 Node 測試；在約十餘秒按停止，K 與工具顯示 `interrupted`、`busy=false`、無錯誤；另查 Windows 程序確認已不存在，未輸出自然結束標記 |

停止驗收曾實際失敗：僅 `turn/interrupt` 時 Node 程序仍在跑；加入背景命令清理後又發現「清理回應早於程序退出」的時序問題。上述結果是補上退出確認後第三次獨立驗收，不把前兩次算成通過。最終命令項目：`exec-772f58f6-e01c-4950-90d2-c1abe26ee8bc`。

## 回歸與界線

- `npm test`：106／106 通過，包含直接權限保存、原生核准／拒絕、過期請求、子代理歸屬檢查、背景命令退出、停止送出中的回合、成果恢復與既有 Pi／Flash 工作流。
- `npm run build:ui`：成功；仍有既有前端單一資源大小警告，不影響本次功能驗收。
- 命令核准、額外權限核准及 GPT 子代理核准有協定／模擬回歸；本輪真實 UI 核准實測是主代理檔案變更，不冒充全部核准種類都已 live 驗證。
- 停止不保證回收由工具刻意脫離管理的獨立服務；本次確認的是原生工具所管理的實際命令。關閉視窗本身也不是停止後端。
- 任意命令建立的所有檔案尚未自動加入成果清單；檔案的 Markdown 絕對路徑連結亦不代表都可直接點開，本次用右側成果預覽驗證交付。
- 這次沒有驗證 Blender、任意外掛／供應商、長上下文壓縮品質、並行多工作區或與 Codex App 的完整速度／費用對照。CLI `Start-K.ps1` 的舊核准流程不在本次桌面變更範圍。
