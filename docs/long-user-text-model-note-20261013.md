## 現況與根因

- 正式 `f5ef4ab` 的 `UserContent` 將普通訊息及換房交接全文呈現；`.user-bubble` 無長度上限或展開操作。這是 UI 顯示缺口，不是原生上下文壓縮失效。
- Pick Me Up 原房 metadata 唯讀查證：只有一筆 Sol → Luna 5.6 切換，屬 `01a13111-abb3-7163-a13b-0f8dd2ee7a2a`；原生紀錄的兩次本人訊息分別在臺灣時間 01:05:54、01:06:05 進入同一回合。沒有第二筆模型切換。
- UI 對每則 user message 只以 `turnId` 查找 modelChanges，沒有像既有 capacity 提示一樣限定一次呈現；同回合的補充訊息因此各出現相同提示。不是實際反覆切換模型，也不是每個新回合必然重複。

## 最小修正

- `frontend/main.jsx`：文字預設顯示約八行，依實際換行高度判斷是否需要「展開全文／收合」；視窗、字體或面板寬度改變時由 ResizeObserver 重算。每則訊息各自保存本次畫面的展開狀態，背景回覆更新不重設；不同聊天室即使有相同訊息 ID 也不共用狀態。
- 保留全文 DOM、既有複製來源與附件列；只收合人類訊息／交接文字，不改送給原生核心的 payload、歷史、摘要、模型或目標。原有引用內容仍用自己的 details，工人通知、助理回覆不套本次收合。
- 收合後保留按鈕焦點與可見位置；使用原生 button 的 Enter／Space、aria-expanded 與 aria-controls，不加設定面板、後端狀態或持久化格式。
- `frontend/style.css`：八行顯示上限與簡短展開按鈕；消除文字段落預設 margin 在收合邊界切到半行的問題，沿用既有字級與行距。
- 模型切換沿用已有第一則同回合 user message 作為提示位置；手動切換與舊 capacity 提示皆只出現一次。後續補充文字仍完整顯示；下次真正切換仍有自己的提示。不改 modelChanges 原始資料或模型路由。
