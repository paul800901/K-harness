## 發現

### F2 應修（已重現）— 聊天室紀錄的更新會被背景存檔蓋掉
呼叫端先 `listMainSessions` 讀取舊紀錄、等待後才 `saveMainSession({...saved, X})`；標題、封存、釘選、模型、工作區、權限都以呼叫端快照為準。背景存檔（例如工人通知標記，`desktop-controller` 的 `persistFlashNotifications`）與本人封存／改名同時發生時，後寫者以舊快照覆蓋。
重現（以真實 `main-sessions` API）：封存＋改名後為 `{archived:true,title:新標題}`，背景存檔後變回 `{archived:false,title:原標題}`。反方向會清掉「工人結果已通知」標記，K 重開後可能再通知一次。
涉及位置：`desktop-controller.mjs` 的 persistFlashNotifications、模型／推理／服務等級切換、metadata（改名／封存／釘選）、open 的工作區遷移、send 的標題；`unified-controller.mjs` 新聊天室；Claude／Gemini 控制器的同類寫法待審查員結果。
修正方向：`main-sessions` 新增在每房存檔佇列內「讀取→修改→寫入」的 `updateMainSession(root, threadId, prior => next)`，呼叫端改用它。

### F1 建議（實測降級）— 未接住的非同步錯誤被靜默吞掉
原以為會讓 K 當掉或跳錯誤視窗。實測 Electron 44.4.5／Node 24.21 主程序：未處理的 Promise 錯誤只印警告到標準輸出，不當機、不跳窗。K 伺服器在 Electron 主程序內，33 處「發射後不管」不會讓 K 當掉，但失敗無人看見。純 Node 的啟動器各處 close() 內部已接住錯誤。可選修正：把未處理錯誤寫入診斷紀錄。

### F3 建議 — 額度查詢的臨時讀取器關閉失敗未接住
`desktop-controller` `usage()` 的 `finally { await reader.close() }` 失敗會讓 `usage()` 拋錯，呼叫端是 `void usage()`。修正：對臨時讀取器的 close 加 `.catch(() => {})`。
