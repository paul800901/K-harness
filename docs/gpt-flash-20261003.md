## 實作與保留的不變條件

- GPT 的 Sol／Luna 子代理仍走 Codex 原生派工；Flash 走 Codex host 限定的本機 `k_gemini` MCP 工具；派工綁定目前原生對話。沒有把 Gemini 模型塞進原生 GPT 子代理欄位，也沒有額度不足就暗換模型。
- `gemini_start`、`gemini_inspect`、`gemini_wait`、`gemini_cancel` 與只讀 `gemini_accounts` 共用既有 bridge；Flash 專用 bridge 不另啟動 Codex 工人核心。
- Claude 繼續走 `k_luna`；補上 lazy bridge 遺漏的 `accounts()` 轉接，使上一批的只讀帳號工具真正可用。
- 正式桌面兩個入口注入同一個 Gemini 帳號管理服務。派工可帶 `accountId`、`handoffFrom`，仍先確認原工作結果／停止，另開新工人處理剩餘任務；不重播整項工作。
- Flash 沿用來源對話的權限。Codex「代我核准」不當作 Flash 完整存取，而是沿用 workspace-write 的限制；原生核准不由 K 一律接受。
- 完成結果只回到自己的原對話，主回合結束後交付；模型已從工具取得完成結果時不再通知。Codex 使用 app-server 原生 `toolOutput`，不偽裝為新的使用者要求。
- 完成通知先保存已嘗試送達標記；送出狀態不確定時不自動重送。停止／關閉須核對工人停止，不能留背景工人或在停止後自行復活。
- 新對話的子代理設定可為 GPT 選 Flash low／medium／high。實際模型目錄與 gateway 能力共同決定可否顯示，沒有合成官方未提供的 Flash 模型列。GPT／Claude 的現有模型選擇不變。
- 未安裝 agy 時，普通 GPT 聊天與原生 GPT 子代理不依賴 agy 啟動；Flash 才回報缺少官方 CLI，沒有改走 API 計費或自動安裝。

## 主代理複查修正

1. 初版 UI 只增加選用參數，實際呼叫端未傳入，會讓 GPT 仍看不到 Flash：改由 `/api/models` 回傳實際 gateway 能力，初載與刷新都讀取；假目錄測試覆蓋 true／false。
2. GPT 的只讀帳號工具不能直接讀 controller 未注入的 manager：改由實際 bridge 取得共用帳號資料；Claude 同類遺漏亦補上。
3. 完成通知欄位初版會被 main-sessions 儲存格式丟棄：新增最小欄位讀寫，普通更新省略該欄位時保留原值；合法 requestId 含點號也須保留。
4. 同一 Codex host 的 gateway URL 保持穩定；停止、切換對話或權限時，先確認並關閉舊 bridge，再以新對話／權限建立。這保留了原有空白對話切出再回來的能力，也避免原生核心持有失效網址；更換工作區／關閉 host 才關 gateway。
5. 完成通知送出中按停止，原先可能尚未取得 turnId 而漏停：加入既有 submission 協調，取得原生回合後中止；若回覆不確定，先讀同一原生對話查明，不重送，也不另設永遠不能恢復的硬鎖。
