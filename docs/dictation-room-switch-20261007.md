# 聽寫轉錄中切換聊天室（2026-10-07）

## 範圍與正式狀態

- 本人要求：停止聽寫、進入轉錄後，切到另一聊天室不應把這段聽寫取消；修好驗證後先停。
- 本批僅工程工作樹實作與隔離驗證，**尚未部署、沒有重啟正式 K、沒有推送 GitHub**。正式版本仍為 `6dbd8cfb733e144c14c35b8077611a0028fa8936`。
- 不操作正式工作、目標、帳號、手機登入、本人麥克風或錄音；不安裝／升級相依。不因上次部署授權而套用本批。

## 直接原因

正式版 `frontend/main.jsx` 的 `Chat` 以 `threadId` 為 React key；切房會卸載來源聊天室。原 `useVoiceComposer` 的清理一律取消 session，原生聽寫取消會中止 HTTP 轉錄請求並忽略晚到結果；後端亦沿用斷線取消。不是 K 整體連線中斷，而是畫面卸載被誤當作取消聽寫。

已辨識完成的文字原本就會保存至該聊天室 `sessionStorage` 草稿；問題是轉錄尚未完成時的生命週期。

## 最小修改

- `frontend/voice-composer.jsx`：主輸入框選擇保留「已停止收音、仍在轉錄」的原生 session。用模組內的暫存 map 保留同一請求，來源聊天室重開時接回同一工作；完成／取消即移除。不改後端、不重試、不保存音訊、不新增工作佇列或常駐服務。
- `frontend/main.jsx`：背景完成時只附加到來源聊天室**當下保存的草稿**，不是開始聽寫時的舊副本；不寫入目前另一聊天室。曾離開來源畫面的工作一律只填草稿，取消先前的自動送出意圖，回到來源時停用「轉錄完成後送出」箭頭並說明。
- 背景辨識失敗／沒有文字，回來源時顯示通知且保留草稿。回來源可取消，晚到結果不得再填入。
- 錄音中／等待麥克風權限時切房仍取消，**不延伸成背景錄音**。視窗隱藏／手機頁面隱藏維持既有取消行為，包含切房後仍等待的轉錄；本批不做關閉 App／重新整理後的語音工作恢復。
- 引用註解未選用背景回填，不會因相同 `threadId` 接走主輸入工作；舊 Web Speech 路徑不變。轉錄中來源輸入框仍維持唯讀。
- `frontend/style.css`：隔離手機驗證直接發現舊 `max-width:1020px` 規則會隱藏 `.composer-note` 的最後一個 span，而聽寫失敗正放在唯一的狀態 span。刪除此過時規則，讓本次失敗／取消／只填草稿提示實際可見；不是以 DOM 存在冒充人看得到。

### 驗證期間的失敗與修正

- 最早探針試圖在轉錄時直接編輯唯讀輸入框而逾時；這是測試假設錯誤。改成離開 A 後更新其既有 `sessionStorage` 草稿槽，驗證晚到資料附加，不改產品的唯讀規則，也不宣稱真人可在轉錄時打字。
- 初期桌面尺寸探針仍使用遠端入口，不能據此宣稱驗到桌面自動送出；最終已改用本機 owner 入口，並測試真正的桌面箭頭。
- 舊手機 CSS 把唯一狀態 span 隱藏，是真正產品問題，不把探針改成只檢查 DOM 以求通過；刪除過時隱藏規則後重新建置、重跑可見性驗證。
- 最終錯誤檢查僅放行轉錄取消與事件串流的 `ERR_ABORTED`，其他失敗請求一律失敗；取消、背景錯誤都與成功案例分開驗證。

## 已知限制

- 桌面與手機驗證採 built UI、獨立假聊天室、Chromium 假音訊與延後回傳的假辨識服務；不宣稱是真人辨識、Android 實機或真 Electron 視窗事件驗收。
- 草稿沿用既有 `sessionStorage`，只處理同頁面切聊天室，不承諾瀏覽器整頁關閉或作業系統終止後恢復未完成錄音／轉錄。
- 原生辨識及主代理的權限、供應商、計費、現有時限不變；沒有送出模型工作，也未修改正式對話。
- Opus 非阻擋備註：回 A 完成後草稿提示仍保留；「先按箭頭→離開→返回 A 才完成」的組合未單獨實測，但相同 `wasDetached` 分支已查碼，未為此擴張機制。
