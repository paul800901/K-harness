## 對話切換

舊流程每次切換都關閉、重新啟動主代理連線，並等 MCP 工具就緒才讀取歷史。同一對話重複點選也走完整流程。

現在重用已初始化的連線，先讀取目標原始歷史，再恢復執行；工具準備在背景進行。工具未就緒時可閱讀、輸入草稿，但不會送出。已就緒的同一對話重複點選不再重新連線。跨對話的事件、權限與停止範圍仍保持分離。

此分離依據官方 [App Server 文件](https://learn.chatgpt.com/docs/app-server) 的 `thread/read` 與 `thread/resume` 行為，不以自製歷史快取代替正式對話紀錄。

### 空白新對話

實測官方執行階段對未送出過的新對話，`thread/read(includeTurns:true)`／`thread/resume` 可能回報 `list_turns is not supported yet`。

已處理「本次連線建立、尚未嘗試送出、設定未變」的新對話：確認其仍為空白 idle 後，沿用原本活躍的 session，讓離開再回來可以正常送出。不把任意讀取錯誤當成空白歷史。重啟後的舊空白紀錄不在這項已驗證支援範圍，未刪除或假造其內容。
