## 建議修正

1. **停用中的送出鈕太顯眼**（低）
   - 空白頁的送出鈕在停用狀態取樣為 `#9f9b96`，是輸入框裡顏色最深的元素，原因是它沿用全域的 `opacity:.45`。
   - 規格 5.5 的要求是：停用時底色用 `--k-line-strong`，箭頭用 `--k-raised`。
2. **截圖假資料的狀態前後不一致**（低，影響驗收證據）
   - 每個場景的側欄都顯示目前對話「需要確認」。但空白場景沒有訊息，標題列也沒有狀態；工作中場景的標題列顯示的是「處理中」。
   - 側欄列狀態（`activityById`）和標題列狀態（`state.questions`／`busy`）來源不同，所以現有截圖無法證明兩者一致。
   - 請把假資料改成和場景一致。正式切換後，也要在真實對話裡確認一次：出現「需要確認」時，側欄和標題列同步顯示。
3. **右側面板預設寬度**（低，可選）
   - 沒有記憶寬度時，面板寬度是 `1fr`，也就是半張紙。只有一個成果時，右側留下一大片空白，對話區被擠到左半邊。
   - 建議沒有記憶寬度時預設約 420px；瀏覽器分頁需要的寬版維持現狀。使用者目前的視窗已記住約 400px 的寬度，所以影響主要是第一次使用。

## 健壯性建議

4. **判斷「新成果」時比較的是數量**（低）
   - 目前的判斷式是 `artifactCount>previous.artifactCount`。如果除了 `connecting` 以外的暫態也短暫回報 0 個成果，數量回升時會被當成新成果，把使用者已收起的面板重新打開；反過來，一個成果被移除、另一個新增時，則不會觸發展開。
   - 建議改成記錄每個對話看過的成果名稱，出現新名稱才算新成果。這是預防性的建議，還沒有實際重現。

## 已確認可以接受、不用改

- 目前所在專案那一列常駐顯示「⋯」，這是刻意設計的規則（`.contains-current`）。
- 深色主題的標誌是一枚亮色圓幣，稍微搶眼，但符合本輪「不破版即可」的範圍；等標誌改成向量圖時再一起處理。
- 對話字級維持 18px 預設、不做遷移，這是使用者的決定。
