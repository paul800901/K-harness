# 目標直接編輯與三核心分開接入（2026-10-05）

## 使用者要求與狀態

目標是討論後產物，AI 可直接修改，不必使用者再次確認；使用者也能查看、修改。後續明確定案：依聊天室主代理，Codex／Claude／Gemini 各接自己的原生目標模式。

本批候選已通過真正 Opus 5.5 複查，尚未部署或推 GitHub，沒有修改使用者的真實目標或中止工作。正式設定讀回仍為前批 `7e2a8593c846e4ea81d3fa431b67d2178ea577e9`，K 啟動器、服務、Electron 及原生核心程序仍存在，尚未確認閒置。固定版本後須確認閒置，才依既有 SOP 套用、正式讀回及推送。

## 根因與最小修正

Codex 原生 AI 的 `update_goal` 只有狀態操作，沒有 objective 參數；K 原本已有 `thread/goal/set` 人用入口，但按鈕一律「更新並執行」。因此 AI 無法直接改文字，錯把目標編輯當成需要 Chrome 的 UI 工作。

- `src/desktop-controller.mjs`：沿用原生 get/set，新增 `editOnly`；只送 objective，不送 status/tokenBudget，不啟動回合或改提交紀錄。人用儲存附帶編輯前的 objective，另一方已更新時拒絕舊稿覆寫。停止／切換期間不再送出尚未送出的修改。
- `src/luna-gateway.mjs`：在既有每聊天室認證 MCP gateway 加可選 `goal_edit`，只有 Codex 主控制器啟用，不新增服務、owner-cookie 存取或瀏覽器依賴。模型參數只有 objective；用 Codex 原生 `x-codex-turn-metadata` 驗證目前主 thread／turn，缺少、中途過期或子代理身分拒絕。保留既有 loopback、bearer、host/origin 限制。
- `frontend/goal-dialog.jsx`：顯示目前主代理核心；Codex 增加「儲存目標」，在工作中也可只改文字。未修改的編輯框跟隨 AI 更新；尚未儲存的人工文字保留，不靜默覆蓋。原有「更新並執行／繼續／停止」維持獨立語意。
- `src/claude-controller.mjs`、`src/gemini-controller.mjs`：拒絕錯送的 editOnly，不能把純儲存請求當成新一輪執行。既有原生 /goal 設定／查看／停止不變。
- 對應四個 test 檔覆蓋工具參數、metadata、主子對話歸屬、舊稿衝突、停止競爭及另外兩家不重啟的邊界。

## 各核心界線

| 主代理 | 修改入口與效果 |
| --- | --- |
| Codex | AI `k_gemini.goal_edit` 與本人「儲存目標」改同一個原生目標；保留目前狀態、預算、用量與建立時間，不二次確認、不自動恢復。工具放既有 gateway 不代表交給 Gemini 做事。 |
| Claude | 現有公開 CLI `/goal <condition>` 是替換並開始原生工作，不是純文字編輯。保留原生操作，介面明示「更新並執行」效果，不增加假的本地目標或重啟備援。 |
| Gemini | 現有 headless `-p /goal` 是原生單次執行入口，沒有公開的執行中純文字修改協定。沿用既有入口與停止，不假造中途編輯或自動重跑。 |

不以子代理核心決定主目標，不跨供應商搬目標，不為三家 UI 一致而補另一套持續執行核心。三家先前原生設定／停止實測見 `native-goals-20261005.md`；本批沒有重新宣稱另外兩家新增 AI 純編輯能力。

## Opus 討論與取捨

- 真正 `claude-opus-5-5` 設計討論 session `b78e74e5-97c6-4a00-8f84-47754596e100`，官方 K 專用 Claude 2.1.289／claude.ai firstParty 訂閱，只讀程式、不接真實使用者工作。
- 原建議用 Codex dynamicTools；實際 0.160.0 產生的 schema 顯示只有 ThreadStartParams 接 dynamicTools，ThreadResumeParams 不接，不能為缺工具的舊聊天室補上。因此改沿用已有 MCP gateway，不修改原生 metadata 或建立替代歷史。
- MCP 原生 metadata 是否包含可信 thread／turn 已由真核心驗證；採用 SDK 2 的 `context.mcpReq._meta`，不是猜測的 `context._meta`。目前實測欄位為 object；沒有證據就拒絕，不以模型參數代替。
- 程式最終複查 session `083484c5-6884-4784-aa39-ba416451e7d4`，實際 model `claude-opus-5-5`、exit 0／success。已看目前差異、來源、測試及三份原生證據，結論無 P1/P2 阻擋，可固定候選。複查明確認可沿用 MCP、原生 metadata 歸屬、短 RPC 停止順序、能力分開及最小改動；沒有宣稱 Opus 自己重跑整套測試。
- 保留 P3：過期草稿被拒時共用 goalError 暫時顯示狀態待確認，實際未覆寫；極短原生 send 收尾期間的 AI 編輯可能明確拒絕，沒有自動重送；AI 後續明確修改採最後寫入，符合雙方直接編輯。均不為本次增加新協調框架。真子代理呼叫拒絕仍只由定向測試及原生 metadata 證據支持，不冒稱已做真子代理探測。
